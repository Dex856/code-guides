1 Setup, compilation and the LeetCode workflow

From a blank file to a running solution: the compiler flags that catch bugs early, and a local test loop.

1.1 Compile and run in one command

# Single file, LeetCode-style solution + your own main()
g++ -std=c++20 -O2 -Wall -Wextra -o sol sol.cpp && ./sol

# The flags that matter
#   -std=c++17|c++20|c++23   choose the standard (LeetCode uses C++17 by default)
#   -O2                      optimise (judge uses -O2); use -O0 for readable debug info
#   -g                       debug symbols (gdb)
#   -Wall -Wextra            warnings = free bug detection
#   -fsanitize=address,undefined   catch out-of-bounds, overflow, UB in tests! (dev only)
#   -D_GLIBCXX_DEBUG         checked STL iterators (catches invalid iterator use)

g++ -std=c++20 -O1 -g -fsanitize=address,undefined sol.cpp -o sol_dbg && ./sol_dbg

# Windows: MSVC via Developer Prompt
#   cl /std:c++20 /EHsc /O2 sol.cpp
# macOS: clang++ -std=c++20 -O2 sol.cpp -o sol
# Fast input for competitive-style problems
#   ios::sync_with_stdio(false); cin.tie(nullptr);
Use sanitizers locally, never on the judge. A 3-second run under -fsanitize=address,undefined finds the out-of-bounds write that would otherwise show up as a mysterious Wrong Answer at test 200. This is the single highest-value habit in this chapter.

1.2 The LeetCode skeleton you actually write

#include <bits/stdc++.h>      // GCC/Clang convenience header used by most competitive C++
using namespace std;

class Solution {
public:
    long long total(const vector<int>& nums) const {   // const& = read-only, no copy
        long long s = 0;                                  // accumulate in 64-bit
        for (int x : nums) s += x;
        return s;
    }
};

#ifdef LOCAL_TEST                       // only compiled when you ask for it
int main() {
    vector<int> v{1, 2, 3};
    cout << Solution().total(v) << '\n';   // 6
    assert(Solution().total({}) == 0);
    cout << "OK\n";
}
#endif
// compile with:  g++ -std=c++20 -O2 -DLOCAL_TEST sol.cpp -o sol
Why <bits/stdc++.h>? It is a GCC header that pulls in the whole standard library — perfect for contests, useless in production (it is non-portable and slows compile times). Know how to write explicit includes too: <vector> <string> <unordered_map> <algorithm> <queue> <numeric> <climits>.

1.4 Local test loop that catches real bugs

// Three levels of testing, in increasing power:
// 1) assert on the examples          2) random stress vs brute force         3) sanitizers

#include <bits/stdc++.h>
using namespace std;

// ---- level 2: stress test -------------------------------------------------
int solveFast(const vector<int>& a);           // your optimised solution
int solveBrute(const vector<int>& a);          // obviously-correct slow version

int main() {
    mt19937 rng(12345);                        // fixed seed = reproducible
    uniform_int_distribution<int> nDist(1, 8), vDist(-5, 5);
    for (int iter = 0; iter < 20000; ++iter) {
        int n = nDist(rng);
        vector<int> a(n);
        for (int& x : a) x = vDist(rng);
        int f = solveFast(a), b = solveBrute(a);
        if (f != b) {
            cout << "MISMATCH on: ";
            for (int x : a) cout << x << ' ';
            cout << "\nfast=" << f << " brute=" << b << '\n';
            return 1;
        }
    }
    cout << "all random tests passed\n";       // then compile with sanitizers
}
The stress-test habit: write the brute force first, then optimise. Twenty thousand random cases under sanitizers finds essentially every indexing and overflow bug in minutes — it is faster than staring at code, and it is how experienced contestants avoid re-submitting 6 times.

2 Types, references and the overflow trap

C++ is statically typed; most wrong answers come from the type you chose, not the algorithm you wrote.

#include <bits/stdc++.h>
using namespace std;
using ll = long long;                 // the alias you will type a thousand times
const int INF = 1e9;                  // "infinity" for int-based graphs
const ll  LINF = 4e18;                // "infinity" for long long

const int MOD = 1'000'000'007;        // digit separators are legal C++14+

int main() {
    int a = 1e9, b = 1e9;
    // int c = a + b;                  // UB (signed overflow) → garbage or wrap
    long long c = 1LL * a + b;         // 2e9, correct

    // The three ways overflow sneaks in:
    // 1) multiplication before promotion
    int x = 100000, y = 100000;
    // int bad = x * y;                // overflow happens in int, BEFORE assignment
    long long good = 1LL * x * y;      // promote one operand to 64-bit first

    // 2) accumulate defaults to the container's type
    vector<int> v(1e5, 1e6);
    // long long wrong = accumulate(v.begin(), v.end(), 0);      // sums in int!
    long long right = accumulate(v.begin(), v.end(), 0LL);       // 0LL forces 64-bit

    // 3) mod arithmetic with negative results
    // (a - b) % MOD can be negative → ((a - b) % MOD + MOD) % MOD
    return 0;
}

2.3 Operators, integer division, and comparison gotchas

7 / 2        //  3   (integer division truncates toward zero)
-7 / 2       // -3   ← C++ truncates; Python floors to -4. Different answers!
-7 % 2       // -1   ← C++ remainder keeps the sign of the dividend
7 % 2        //  1
// Floor division & positive modulo, the safe versions:
int floordiv(int a, int b) { return (a - (a % b + b) % b) / b; }
int mod(int a, int m)      { return ((a % m) + m) % m; }

// Comparison and boolean ops
a == b   a != b   a < b   a <= b
a && b   a || b   !a            // short-circuit: b is not evaluated if a decides it
x ? y : z                       // ternary
// Bitwise (ch. 10): a & b   a | b   a ^ b   ~a   a << k   a >> k

// The classic pitfall: mixing signed and unsigned
vector<int> v{1,2,3};
// for (int i = 0; i < v.size(); ++i)      // warning: signed/unsigned comparison
for (size_t i = 0; i < v.size(); ++i)      // clean
for (int i = 0; i < (int)v.size(); ++i)    // or cast (fine for n < 2^31)
for (size_t i = 0; i + 1 < v.size(); ++i)  // the idiom that avoids v[i+1] overrun

// Comparing doubles: never ==
bool close(double a, double b, double eps = 1e-9) { return fabs(a - b) < eps; }
Subscript with a negative index is UB, not an exception. C++ has no bounds checking on v[i]. v.at(i) throws and is the debugging variant — use it while developing, and use -D_GLIBCXX_DEBUG or ASan to catch the rest.

3 Strings and characters

C++ strings are mutable, indexable byte arrays with a rich API — much closer to Python lists than Python strings.

3.1 The operations you will type most

string s = "hello world";

// Access and mutation (C++ strings ARE mutable)

s[0] = 'H';                            // "Hello world"

s.front(); s.at(1);                    // 'e' (at() checks range, throws)

s.substr(6)                            // "world"   (to the end)

Three classic string traps: (1) s.substr(i, len) — the second parameter is a length; s.substr(i, j-i) for [i, j). (2) s.find(c) returns string::npos (a huge unsigned value), not −1 — always compare against npos; and never write if (s.find(c) >= 0) (always true, unsigned). 4 vector, arrays and grids

The workhorse container: growth rules, reserve, 2D grids, and the iterator model you must understand.

4.1 Creating and using a vector

#include <bits/stdc++.h>
using namespace std;

vector<int> v;                        // empty
vector<int> a(5);                     // 5 zeros:      {0,0,0,0,0}
vector<int> b(5, -1);                 // 5 copies of -1
vector<int> c{1, 2, 3};               // initialiser list
vector<int> d(c);                     // copy (O(n))
vector<int> e(c.begin(), c.end());    // from iterators
int arr[] = {1,2,3};
vector<int> f(arr, arr + 3);          // from a C array

// Sizing and capacity
v.size(); v.empty(); v.capacity();
v.resize(10);                         // grow (zero-fills) or shrink
v.resize(10, 7);                      // fill new slots with 7
v.reserve(1000);                      // preallocate: avoids repeated reallocation
v.shrink_to_fit();                    // release spare capacity (rarely needed)

// Access
v[0]; v.at(0); v.front(); v.back();
int* p = v.data();                    // raw pointer to the buffer

// Add / remove
v.push_back(9);                       // amortised O(1)
v.pop_back();                         // O(1)
v.insert(v.begin() + 1, 42);          // O(n) — shifts the tail
v.insert(v.end(), 3, 5);              // insert 3 copies of 5 at the end
v.erase(v.begin());                   // O(n)
v.erase(v.begin() + 1, v.begin() + 3); // erase a range [1,3)
v.assign(4, 0);                       // replace contents with four 0s
v.clear();                            // size 0, capacity kept

// Iterators (the general way to talk about positions)
v.begin(); v.end();                   // [begin, end) — half-open
v.rbegin(); v.rend();                 // reverse
for (auto it = v.begin(); it != v.end(); ++it) cout << *it;

4.2 2D vectors and grids — the LeetCode staple

// ---- construction -------------------------------------------------------
int m = 3, n = 4;
vector<vector<int>> g(m, vector<int>(n, 0));      // 3×4 of zeros  ★ the standard form
vector<vector<int>> g2(m);                          // 3 empty rows
for (auto& row : g2) row.assign(n, 0);              // then fill

// from an initialiser list
vector<vector<int>> grid = {{1,2,3},{4,5,6},{7,8,9}};

// ---- traversal ----------------------------------------------------------
int R = grid.size(), C = grid[0].size();
for (int i = 0; i < R; ++i)
    for (int j = 0; j < C; ++j)
        /* grid[i][j] */;

// ---- neighbour moves: two idioms ---------------------------------------
const int di[4] = {-1, 1, 0, 0};       // up, down, left, right
const int dj[4] = {0, 0, -1, 1};
for (int d = 0; d < 4; ++d) {
    int ni = i + di[d], nj = j + dj[d];
    if (ni < 0 || ni >= R || nj < 0 || nj >= C) continue;   // bounds check FIRST
    /* visit grid[ni][nj] */
}
// 8-directional (king moves)
const int dx8[8] = {-1,-1,-1, 0, 0, 1, 1, 1};
const int dy8[8] = {-1, 0, 1,-1, 1,-1, 0, 1};

// ---- in-place 90° rotation of an n×n matrix ----------------------------
for (int i = 0; i < n; ++i)
    for (int j = i + 1; j < n; ++j)
        swap(g[i][j], g[j][i]);          // transpose
for (auto& row : g) reverse(row.begin(), row.end());   // then mirror → rotated clockwise

// ---- spiral traversal skeleton -----------------------------------------
int top = 0, bottom = R - 1, left = 0, right = C - 1;
while (top <= bottom && left <= right) {
    for (int j = left; j <= right; ++j) visit(g[top][j]);      ++top;
    for (int i = top; i <= bottom; ++i) visit(g[i][right]);    --right;
    if (top <= bottom) { for (int j = right; j >= left; --j) visit(g[bottom][j]); --bottom; }
    if (left <= right) { for (int i = bottom; i >= top; --i) visit(g[i][left]);  ++left;  }
}

// ---- flattening a grid into 1D (useful for DSU/visited arrays) ---------
int id = i * C + j;          int i2 = id / C, j2 = id % C;
Grid checklist: always compute R/C once; guard grid.empty() before grid[0]; do bounds checks before indexing; prefer vector<vector<int>> for clarity and a flat vector<int> of size R·C when you need speed (better cache locality). For visited, a 2D vector<char> is often faster to initialise than vector<bool>.

// ★ Monotonic deque — sliding window maximum in O(n) (ch. 11 pattern)
vector<int> maxSlidingWindow(const vector<int>& a, int k) {
    deque<int> idx;                                  // indices, values DECREASING
    vector<int> res;
    for (int i = 0; i < (int)a.size(); ++i) {
        while (!idx.empty() && idx.front() <= i - k) idx.pop_front();   // drop expired
        while (!idx.empty() && a[idx.back()] <= a[i]) idx.pop_back();   // keep monotonic
        idx.push_back(i);
        if (i >= k - 1) res.push_back(a[idx.front()]);                  // window max
    }
    return res;
}

// Monotonic stack — next greater element in O(n)
vector<int> nextGreater(const vector<int>& a) {
    int n = a.size();
    vector<int> res(n, -1);
    stack<int> st;                                    // indices, decreasing values
    for (int i = 0; i < n; ++i) {
        while (!st.empty() && a[st.top()] < a[i]) { res[st.top()] = a[i]; st.pop(); }
        st.push(i);
    }
    return res;
}

The comparator trap that costs the most submissions. In priority_queue, the comparator answers “should a come after b?” — the element the comparator calls “less” ends up on top. So greater<int> gives a min-heap and less<int> a max-heap. Also, a custom comparator must be a strict weak ordering (irreflexive, transitive): writing >= instead of > can make the heap corrupt the array with no error message.

// Use when: "minimise the maximum", "maximise the minimum", "find the smallest
// value such that a monotonic condition holds". Write the feasibility check first!
//
// Example shape: split array into m parts minimising the largest sum.
bool feasible(const vector<int>& a, int m, long long cap) {
    int parts = 1; long long cur = 0;
    for (int x : a) {
        if (cur + x > cap) { ++parts; cur = 0; }
        cur += x;
    }
    return parts <= m;
}
long long minLargestSum(vector<int>& a, int m) {
    long long lo = *max_element(a.begin(), a.end());     // feasibility bound
    long long hi = accumulate(a.begin(), a.end(), 0LL);
    while (lo < hi) {
        long long mid = lo + (hi - lo) / 2;              // ← never (lo+hi)/2 (overflow)
        if (feasible(a, m, mid)) hi = mid; else lo = mid + 1;
    }
    return lo;
}

// ---- Binary search over reals (fixed 60–100 iterations, no epsilon loop) --
double solve(double lo, double hi) {
    for (int iter = 0; iter < 80; ++iter) {
        double mid = (lo + hi) / 2;
        if (ok(mid)) hi = mid; else lo = mid;
    }
    return lo;
}

// ---- Searching in a rotated sorted array (classic twist) -----------------
int searchRotated(vector<int>& a, int target) {
    int lo = 0, hi = a.size() - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] == target) return mid;
        if (a[lo] <= a[mid]) {                            // left half sorted
            if (a[lo] <= target && target < a[mid]) hi = mid - 1; else lo = mid + 1;
        } else {                                          // right half sorted
            if (a[mid] < target && target <= a[hi]) lo = mid + 1; else hi = mid - 1;
        }
    }
    return -1;
}
Overflow in binary search: (lo + hi) / 2 overflows when both are near 10¹⁸. Always write lo + (hi - lo) / 2. And use long long for the bounds in answer-search problems even when the array is int — caps are usually sums.

    }
    tail->next = a ? a : b;
    return dummy.next;
}

// Iterative inorder (needed when recursion depth is a problem)
vector<int> inorderIt(TreeNode* root) {
    vector<int> out; stack<TreeNode*> st; TreeNode* cur = root;
    while (cur || !st.empty()) {
        while (cur) { st.push(cur); cur = cur->left; }
        cur = st.top(); st.pop();
        out.push_back(cur->val);
        cur = cur->right;
    }
    return out;
}

// Level-order with a queue, level by level
vector<vector<int>> levelOrder(TreeNode* root) {
    vector<vector<int>> res; if (!root) return res;
    queue<TreeNode*> q; q.push(root);
    while (!q.empty()) {
        int sz = q.size(); vector<int> level;
        while (sz--) {
            TreeNode* n = q.front(); q.pop();
            level.push_back(n->val);
            if (n->left)  q.push(n->left);
            if (n->right) q.push(n->right);
        }
        res.push_back(level);
    }
    return res;
}
// Depth / height, and validating a BST
int depth(TreeNode* r) { return r ? 1 + max(depth(r->left), depth(r->right)) : 0; }
bool isBST(TreeNode* r, long long lo = LLONG_MIN, long long hi = LLONG_MAX) {
    if (!r) return true;
    if (r->val <= lo || r->val >= hi) return false;      // long long bounds avoid INT_ edge cases
    return isBST(r->left, lo, r->val) && isBST(r->right, r->val, hi);
}
Pointer habits for tree/list problems: check nullptr before dereferencing (if (!node) return ...); use a local long long range when validating BSTs to dodge INT_MIN/INT_MAX edge cases; prefer a stack-based traversal if depth may exceed ~10⁴ (no C++ recursion limit, but the C stack can still overflow); and remember LeetCode nodes are heap-allocated — never delete them, and never return a pointer to a local.

13.1 Graph traversal: adjacency list, BFS, DFS, components

#include <bits/stdc++.h>
using namespace std;

int n;                                   // number of nodes
vector<vector<int>> adj;                 // adj[u] = neighbours of u

void buildGraph(int n_, const vector<pair<int,int>>& edges, bool undirected = true) {
    n = n_;
    adj.assign(n, {});
    for (auto [u, v] : edges) { adj[u].push_back(v); if (undirected) adj[v].push_back(u); }
}

// ---- BFS: shortest path in an unweighted graph --------------------------
vector<int> bfs(int src) {
    vector<int> dist(n, -1);
    queue<int> q;
    dist[src] = 0; q.push(src);
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (int v : adj[u])
            if (dist[v] == -1) { dist[v] = dist[u] + 1; q.push(v); }
    }
    return dist;                          // dist[v] == -1 ⇒ unreachable
}

// ---- Multi-source BFS (rotten oranges, walls and gates) -----------------
vector<int> bfsMulti(const vector<int>& sources) {
    vector<int> dist(n, -1);
    queue<int> q;
    for (int s : sources) { dist[s] = 0; q.push(s); }
    while (!q.empty()) {
        int u = q.front(); q.pop();
        for (int v : adj[u]) if (dist[v] == -1) { dist[v] = dist[u] + 1; q.push(v); }
    }
    return dist;
}

// ---- DFS with a recursive lambda (C++14 generic lambda) -----------------
int countComponents() {
    vector<char> seen(n, 0);
    int comps = 0;
    auto dfs = [&](auto&& self, int u) -> void {
        seen[u] = 1;
        for (int v : adj[u]) if (!seen[v]) self(self, v);
    };
    for (int u = 0; u < n; ++u) if (!seen[u]) { ++comps; dfs(dfs, u); }
    return comps;
}

        return false;
    };
    for (int u = 0; u < n; ++u) if (color[u] == 0 && dfs(dfs, u)) return true;
    return false;
}

// ---- Topological sort: Kahn's algorithm (also detects cycles) ----------
vector<int> topoSort() {
    vector<int> indeg(n, 0);
    for (int u = 0; u < n; ++u) for (int v : adj[u]) ++indeg[v];
    queue<int> q;
    for (int u = 0; u < n; ++u) if (indeg[u] == 0) q.push(u);
    vector<int> order;
    while (!q.empty()) {
        int u = q.front(); q.pop();
        order.push_back(u);
        for (int v : adj[u]) if (--indeg[v] == 0) q.push(v);
    }
    if ((int)order.size() != n) return {};           // cycle: no valid order
    return order;
}

// ---- Dijkstra: weighted shortest path, non-negative weights ------------
vector<long long> dijkstra(int src, const vector<vector<pair<int,int>>>& wadj) {
    const long long INF = LLONG_MAX / 4;
    vector<long long> dist(n, INF);
    priority_queue<pair<long long,int>, vector<pair<long long,int>>, greater<>> pq;
    dist[src] = 0; pq.push({0, src});
    while (!pq.empty()) {
        auto [d, u] = pq.top(); pq.pop();
        if (d > dist[u]) continue;                   // stale entry
        for (auto [v, w] : wadj[u])
            if (d + w < dist[v]) { dist[v] = d + w; pq.push({dist[v], v}); }
    }
    return dist;
}

// ---- Grid BFS (no adjacency list needed) -------------------------------
int shortestPathGrid(const vector<string>& g, pair<int,int> s, pair<int,int> t) {
    int R = g.size(), C = g[0].size();
    vector<vector<int>> dist(R, vector<int>(C, -1));
    const int di[4] = {-1,1,0,0}, dj[4] = {0,0,-1,1};
    queue<pair<int,int>> q;
    dist[s.first][s.second] = 0; q.push(s);
    while (!q.empty()) {
        auto [i, j] = q.front(); q.pop();
        if (i == t.first && j == t.second) return dist[i][j];
        for (int d = 0; d < 4; ++d) {
            int ni = i + di[d], nj = j + dj[d];
            if (ni < 0 || ni >= R || nj < 0 || nj >= C) continue;
            if (g[ni][nj] == '#' || dist[ni][nj] != -1) continue;   // wall / visited
            dist[ni][nj] = dist[i][j] + 1; q.push({ni, nj});
        }
    }
    return -1;
}
Which traversal? Unweighted shortest path → BFS. Any reachability/ordering → DFS. Weighted non-negative → Dijkstra. Negative edges → Bellman-Ford (V−1 relaxations). All-pairs, small n → Floyd-Warshall. Ordering with prerequisites → topological sort (and a cycle means “impossible”).

13.2 Union-Find (DSU) — connectivity made trivial

struct DSU {
    vector<int> parent, rank_, size_;
    explicit DSU(int n) : parent(n), rank_(n, 0), size_(n, 1) {
        iota(parent.begin(), parent.end(), 0);          // each node is its own set
    }
    int find(int x) {                                   // path compression
        return parent[x] == x ? x : parent[x] = find(parent[x]);
    }
    bool unite(int a, int b) {                          // union by rank
        a = find(a); b = find(b);
        if (a == b) return false;                       // already connected
        if (rank_[a] < rank_[b]) swap(a, b);
        parent[b] = a;
        size_[a] += size_[b];
        if (rank_[a] == rank_[b]) ++rank_[a];
        return true;
    }
    bool connected(int a, int b) { return find(a) == find(b); }
    int componentSize(int x) { return size_[find(x)]; }
    int countComponents(int n) {                        // O(n) call, not O(1)
        int c = 0; for (int i = 0; i < n; ++i) if (find(i) == i) ++c; return c;
    }
};

// Usage patterns
// • Kruskal MST: sort edges by weight, unite, keep edges that merged two sets
// • Number of provinces / friend circles: union all edges, count distinct roots
// • Redundant connection: the first edge whose endpoints are already connected
// • Accounts merge / email grouping: union by shared email, then bucket by root
// • Grid islands (dynamic): id = i*C + j, union with right/down neighbours

With path compression + union by rank, the amortised cost per operation is O(α(n)) — effectively constant (α is the inverse Ackermann function, < 5 for any n you will ever see). Say “near-O(1) amortised” in interviews.

// Template A — integer answer, find the SMALLEST feasible value
long long solve(long long lo, long long hi, const function<bool(long long)>& ok) {
    while (lo < hi) {
        long long mid = lo + (hi - lo) / 2;
        if (ok(mid)) hi = mid;            // feasible → try smaller
        else         lo = mid + 1;        // infeasible → must go bigger
    }
    return lo;                            // lo == hi == answer
}

// Template B — integer answer, find the LARGEST feasible value
long long solveMax(long long lo, long long hi, const function<bool(long long)>& ok) {
    while (lo < hi) {
        long long mid = lo + (hi - lo + 1) / 2;   // ↑ bias up to avoid an infinite loop
        if (ok(mid)) lo = mid;
        else         hi = mid - 1;
    }
    return lo;
}

// Template C — floating point answer (never loop on epsilon; fix the iteration count)
double solveReal(double lo, double hi, const function<bool(double)>& ok) {
    for (int iter = 0; iter < 100; ++iter) {
        double mid = lo + (hi - lo) / 2;
        if (ok(mid)) hi = mid; else lo = mid;
    }
    return lo;                            // ~1e-30 precision after 100 halvings
}

13.4 Dynamic programming — the four shapes

// DP = (1) define the state, (2) write the transition, (3) set the base case,
//      (4) choose the iteration order (or memoise).

// ---- Shape 1: 1D DP (linear recurrences) --------------------------------
int climbStairs(int n) {
    if (n <= 2) return n;
    int a = 1, b = 2;                         // rolling variables instead of an array
    for (int i = 3; i <= n; ++i) { int c = a + b; a = b; b = c; }
    return b;
}

// ---- Shape 2: 1D DP over a sequence (LIS, house robber) -----------------
int rob(const vector<int>& nums) {            // no two adjacent
    int take = 0, skip = 0;
    for (int x : nums) { int nt = skip + x; skip = max(skip, take); take = nt; }
    return max(take, skip);
}
int lisLength(const vector<int>& a) {          // O(n log n) patience sorting
    vector<int> tails;
    for (int x : a) {
        auto it = lower_bound(tails.begin(), tails.end(), x);
        if (it == tails.end()) tails.push_back(x);
        else *it = x;
    }
    return (int)tails.size();
}

// ---- Shape 3: 2D DP (grids, edit distance, knapsack) --------------------
int editDistance(const string& a, const string& b) {
    int n = a.size(), m = b.size();
    vector<vector<int>> dp(n + 1, vector<int>(m + 1, 0));
    for (int i = 0; i <= n; ++i) dp[i][0] = i;          // base cases
    for (int j = 0; j <= m; ++j) dp[0][j] = j;
    for (int i = 1; i <= n; ++i)
        for (int j = 1; j <= m; ++j)
            dp[i][j] = (a[i-1] == b[j-1])
                ? dp[i-1][j-1]
                : 1 + min({dp[i-1][j], dp[i][j-1], dp[i-1][j-1]});   // delete, insert, replace
    return dp[n][m];
}

// 0/1 knapsack, 1D rolling array (capacity iterated DOWNWARD)
int knapsack(const vector<int>& wt, const vector<int>& val, int cap) {
    vector<int> dp(cap + 1, 0);
    for (int i = 0; i < (int)wt.size(); ++i)
        for (int c = cap; c >= wt[i]; --c)                 // ← downward: each item once
            dp[c] = max(dp[c], dp[c - wt[i]] + val[i]);
    return dp[cap];
}
// Unbounded knapsack / coin change (fewest coins): iterate capacity UPWARD
int coinChange(const vector<int>& coins, int amount) {
    const int INF = 1e9;
    vector<int> dp(amount + 1, INF);
    dp[0] = 0;
    for (int c = 1; c <= amount; ++c)
        for (int coin : coins) if (coin <= c) dp[c] = min(dp[c], dp[c - coin] + 1);
    return dp[amount] == INF ? -1 : dp[amount];
}

// ---- Shape 4: interval DP (palindromes, matrix chain, burst balloons) ---
int longestPalindromeSubseq(const string& s) {              // O(n²)
    int n = s.size();
    vector<vector<int>> dp(n, vector<int>(n, 0));
    for (int i = 0; i < n; ++i) dp[i][i] = 1;
    for (int len = 2; len <= n; ++len)
        for (int l = 0; l + len - 1 < n; ++l) {
            int r = l + len - 1;
            dp[l][r] = (s[l] == s[r]) ? dp[l+1][r-1] + 2
                                      : max(dp[l+1][r], dp[l][r-1]);
        }
    return dp[0][n-1];
}

// ---- Recursion + memoisation (equivalent, often easier to write) --------
unordered_map<long long,long long> memo;
long long f(int i, int j) {

    if (memo.count(key)) return memo[key];

// ---- Trie (prefix tree) -------------------------------------------------
struct Trie {
    struct Node { int nxt[26]; bool isWord = false; Node() { fill(nxt, nxt + 26, -1); } };
    vector<Node> t{Node{}};                       // t[0] is the root
    void insert(const string& w) {
        int cur = 0;
        for (char ch : w) {
            int c = ch - 'a';
            if (t[cur].nxt[c] == -1) { t[cur].nxt[c] = t.size(); t.push_back(Node{}); }
            cur = t[cur].nxt[c];
        }
        t[cur].isWord = true;
    }
    bool contains(const string& w) {
        int cur = 0;
        for (char ch : w) { cur = t[cur].nxt[ch - 'a']; if (cur == -1) return false; }
        return t[cur].isWord;
    }
    bool startsWith(const string& p) {
        int cur = 0;
        for (char ch : p) { cur = t[cur].nxt[ch - 'a']; if (cur == -1) return false; }
        return true;
    }
};

// ---- Backtracking: subsets, permutations, combinations, N-Queens --------
void subsets(const vector<int>& a, int i, vector<int>& cur, vector<vector<int>>& out) {
    if (i == (int)a.size()) { out.push_back(cur); return; }
    subsets(a, i + 1, cur, out);                 // exclude a[i]
    cur.push_back(a[i]);
    subsets(a, i + 1, cur, out);                 // include a[i]
    cur.pop_back();                              // ← always undo
}
void permutations(vector<int>& a, int k, vector<vector<int>>& out) {
    if (k == (int)a.size()) { out.push_back(a); return; }
    for (int i = k; i < (int)a.size(); ++i) {
        swap(a[k], a[i]);
        permutations(a, k + 1, out);
        swap(a[k], a[i]);                        // restore
    }
}
void combinations(int n, int k, int start, vector<int>& cur, vector<vector<int>>& out) {
    if ((int)cur.size() == k) { out.push_back(cur); return; }
    for (int v = start; v <= n; ++v) {
        cur.push_back(v);
        combinations(n, k, v + 1, cur, out);     // v+1 ⇒ no reuse, no duplicates
        cur.pop_back();
    }
}

// ---- Two heaps for a streaming median ---------------------------------
// low: max-heap of the smaller half; high: min-heap of the larger half
// invariant: low.size() == high.size() or low.size() == high.size() + 1
void addNum(int x, priority_queue<int>& low, priority_queue<int, vector<int>, greater<int>>& high) {
    if (low.empty() || x <= low.top()) low.push(x); else high.push(x);
    if (low.size() > high.size() + 1) { high.push(low.top()); low.pop(); }
    else if (high.size() > low.size()) { low.push(high.top()); high.pop(); }
}
double median(const priority_queue<int>& low, const priority_queue<int, vector<int>, greater<int>>& high) {
    if (low.size() == high.size()) return (low.top() + high.top()) / 2.0;
    return low.top();
}

15 Interview questions with answers

The C++ questions that come up in interviews and screens, answered the way you should say them out loud.

Language & semantics

  1. What is the difference between a pointer and a reference? A pointer is an object holding an address (nullable, reassignable, arithmetic); a reference is an alias bound at creation (not null, not rebindable, no arithmetic).
  2. Why const T& as the parameter default? No copy (O(1) for containers), no accidental mutation, and it binds temporaries.
  3. What is a dangling reference/pointer? A reference to an object whose lifetime ended — reading it is UB. Common sources: returning a local by reference, storing string_view/const char* to a temporary.
  4. What is the difference between struct and class? Only default access (public vs private) and default inheritance. Everything else is identical.
  5. What does static mean in different places? Inside a function: one instance for the program’s lifetime. At file scope: internal linkage. For a class member: shared by all instances, no this.
  6. RAII in one sentence. Bind a resource’s lifetime to an object’s lifetime: acquire in the constructor, release in the destructor, so vector/string/unique_ptr free memory automatically — even on exceptions.
  7. move vs copy? A copy duplicates the buffer; a move steals the pointer and leaves the source empty. Use std::move when you will not touch the source again.
  8. Why is vector<bool> special? It is a bitset optimisation: v[i] returns a proxy, not bool&. Prefer vector<char> or bitset when that matters.

Containers, algorithms, complexity

  1. vector vs list? vector is contiguous: O(1) indexing, cache-friendly, but O(n) middle insert. list has O(1) middle insert/erase but pointer-chasing, no indexing. In practice vector usually wins because memory bandwidth dominates.
  2. map vs unordered_map? Tree vs hash: O(log n) with ordering/lower_bound vs O(1) average with no order and possible degradation. Reserve/normalise keys to keep hashes healthy.
  3. What does sort guarantee? O(n log n) comparisons (introsort), not stable. Use stable_sort when equal elements must keep their relative order.
  4. What is a strict weak ordering? A comparator where cmp(a,a) is false and the relation is transitive. Violating it (e.g. <=) is UB inside sort.
  5. How do you find the k-th largest? nth_element (O(n) average), a min-heap of size k (O(n log k)), or quickselect. For a stream, min-heap of size k is the answer.
  6. lower_bound vs upper_bound? First ≥ x vs first > x — the pair gives the count of equal elements and the insertion range.
  7. Why reserve()? Avoids reallocation/rehashing: O(n) pushes become truly O(1) amortised without data movement, and iterators/pointers stay valid.
  8. What is iterator invalidation? Operations that move the underlying storage (reallocation, erase/insert in vectors, rehash) invalidate iterators/pointers/references into it — using them is UB.
  9. When can you not use binary_search? When the range is unsorted, or when the predicate is not monotone. For “binary search on the answer” the sequence is implicit, so you write the lo/hi loop yourself.
  10. Top-K in a stream? Min-heap capped at k: O(n log k) time, O(k) space.

Pitfalls & performance

  1. Where does signed overflow bite? Sums/products that exceed 2·10⁹, (lo+hi)/2, accumulate(…, 0), counting pairs n(n−1)/2, i*i in sieves.
  2. How do you debug a wrong answer fast? Print inputs at the failing size; compare with brute force on random small cases; compile with -fsanitize=address,undefined; check overflow first, then off-by-one, then container assumptions.
  3. Why might a correct solution TLE? Hash degradation, endl flushing, no sync_with_stdio(false), O(n²) in a hidden case, std::function in deep recursion, copying containers per call.
  4. How do you allocate a 10⁷-element array safely? Heap (vector) or static/global — never a plain local array (stack overflow).
  5. What is cache locality and why care? Sequential access is 10–100× faster than random access at scale; it is why contiguous vector and flat arrays beat pointer structures.
  6. Fixed-size vs dynamic arrays for speed? Stack int a[N] or array<int,N> avoids allocation entirely; use them when N is known and small enough for the stack (≲ a few MB).

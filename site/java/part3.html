3 Strings & characters

Java strings are immutable objects, not arrays. That single fact explains the O(n²) loops, the == failures, and why StringBuilder exists.

Strings without the O(n²) trap

A large share of interview problems are string problems: palindromes, anagrams, parsing, substrings, encoding. Almost all of them are solved with nine methods — length, charAt, toCharArray, substring, indexOf, split, equals, compareTo, and StringBuilder. This chapter is those nine, their exact index conventions, and the four ways people lose submissions with them.

3.1 Immutability and the cost it imposes

String s = "abc";
s.toUpperCase();              // returns "ABC" — s is still "abc"
s = s.toUpperCase();          // ✅ rebind the variable
String t = s.substring(1);    // "BC" is a NEW string; s is untouched

// The O(n^2) loop: 10^5 concatenations of 1 char copies ~5 x 10^9 chars
String bad = "";
for (int i = 0; i < n; i++) bad += 'a';        // ❌ quadratic in Java (unlike C++ std::string)

StringBuilder sb = new StringBuilder();
for (int i = 0; i < n; i++) sb.append('a');    // ✅ amortised O(n)
String good = sb.toString();

sb.reverse();                    // in-place reversal
sb.setCharAt(2, 'X');            // mutate one char
sb.deleteCharAt(0);              // O(k) shift
sb.insert(0, 'Z');               // O(k) — avoid in loops
System.out.println(sb.charAt(0));
Do not “fix” it with StringBuffer. StringBuffer is the synchronised (thread-safe) sibling; it is strictly slower and pointless in a single-threaded judge.

3.3 The four string traps that cost submissions

1 · substring(begin, end)

end is exclusive, so s.substring(i, i+1) is a one-char string. Mixing in the “take a single char” instinct from Python (s[i:]) produces off-by-one bugs at the last character.

2 · split takes a regex

s.split(".") returns an empty array (the dot matches everything). Escape metacharacters: split("\\."), split("\\|"), split("\\s+"). To split on a plain string without regex reasoning, use Pattern.quote(t).

3 · Trailing empties vanish

"a,b,,".split(",") → ["a","b"]. Pass a negative limit to keep them: split(",", -1) → ["a","b","",""].

4 · == on strings

Literals are interned, so "ab" == "a" + "b" is true by compile-time constant folding — while new String("ab") == "ab" is false. Any string produced at runtime must be compared with equals.

    int i = 0, j = s.length() - 1;
    while (i < j) if (s.charAt(i++) != s.charAt(j--)) return false;

boolean isAnagram(String a, String b) {
    if (a.length() != b.length()) return false;
    int[] cnt = new int[26];
    for (int i = 0; i < a.length(); i++) { cnt[a.charAt(i) - 'a']++; cnt[b.charAt(i) - 'a']--; }
    for (int c : cnt) if (c != 0) return false;
    return true;
}

// Case/space-insensitive palindrome over letters+digits only
boolean isPalindrome2(String s) {
    int i = 0, j = s.length() - 1;
    while (i < j) {
        while (i < j && !Character.isLetterOrDigit(s.charAt(i))) i++;
        while (i < j && !Character.isLetterOrDigit(s.charAt(j))) j--;
        if (Character.toLowerCase(s.charAt(i)) != Character.toLowerCase(s.charAt(j))) return false;
        i++; j--;
    }
    return true;
}   // O(n) time · O(1) space

4 Arrays, lists and 2-D grids

Arrays are the fastest data structure in Java. Most “Java is slow” stories are really stories about ArrayList<Integer> where an int[] belonged.

Arrays, ArrayList and grids

Half of all LeetCode problems are array manipulation: two pointers, sorting, prefix sums, in-place modification, matrices. This chapter covers the array APIs (Arrays.*, System.arraycopy), the ArrayList methods with their sneaky overloads, 2-D grid traversal, and the in-place techniques (cyclic sort, marking, index-as-key) that turn O(n) space into O(1).

// Rotating a matrix 90° clockwise, in place: transpose + reverse each row
void rotate(int[][] m) {
    int n = m.length;
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++) { int t = m[i][j]; m[i][j] = m[j][i]; m[j][i] = t; }
    for (int[] row : m) { for (int l = 0, r = n - 1; l < r; l++, r--) { int t = row[l]; row[l] = row[r]; row[r] = t; } }
}   // O(n^2) time · O(1) space

// In-place spiral read of a matrix (boundary-shrinking skeleton)
List<Integer> spiral(int[][] a) {
    List<Integer> out = new ArrayList<>();
    int top = 0, bot = a.length - 1, left = 0, right = a[0].length - 1;
    while (top <= bot && left <= right) {
        for (int c = left; c <= right; c++) out.add(a[top][c]);  top++;
        for (int r = top; r <= bot; r++)  out.add(a[r][right]);  right--;
        if (top <= bot) for (int c = right; c >= left; c--) out.add(a[bot][c]); bot--;
        if (left <= right) for (int r = bot; r >= top; r--) out.add(a[r][left]); left++;
    }
    return out;
}   // O(m·n) time · O(1) extra space
Warm-up exercises for grids: transpose, rotate 90°/180°, reverse rows/cols, spiral order, set-matrix-zeroes (use first row/col as the flag array), diagonal traversal, boundary walk. All are variations of the same index arithmetic above — do them once and grid problems stop being intimidating.

// Remove duplicates from a sorted array, return the new length (classic two-pointer)
int removeDuplicates(int[] a) {
    int w = 0;                                    // write pointer
    for (int r = 0; r < a.length; r++)
        if (w == 0 || a[r] != a[w - 1]) a[w++] = a[r];
    return w;
}   // O(n) time · O(1) space

// Cyclic sort: put every value at its own index, then find the first mismatch
int firstMissingPositive(int[] a) {
    int n = a.length;
    for (int i = 0; i < n; i++)
        while (a[i] > 0 && a[i] <= n && a[a[i] - 1] != a[i]) {
            int t = a[i]; a[i] = a[t - 1]; a[t - 1] = t;
        }
    for (int i = 0; i < n; i++) if (a[i] != i + 1) return i + 1;
    return n + 1;
}   // O(n) time · O(1) space
Careful with the cyclic-sort swap: the loop must terminate when a value is already in place. Writing swap(i, a[i]-1) without the a[a[i]-1] != a[i] guard loops forever on duplicates.

4.5 Prefix sums — the one trick behind a hundred problems

// 1-D: sum(l..r) answered in O(1) after O(n) preprocessing
int[] pre = new int[n + 1];
for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + a[i];
// sum of a[l..r] inclusive:
int s = pre[r + 1] - pre[l];

// 2-D: sum of a sub-rectangle in O(1)
int[][] p = new int[m + 1][n + 1];
for (int i = 0; i < m; i++)
    for (int j = 0; j < n; j++)
        p[i+1][j+1] = g[i][j] + p[i][j+1] + p[i+1][j] - p[i][j];
// rectangle with corners (r1,c1)..(r2,c2) inclusive:
int rect = p[r2+1][c2+1] - p[r1][c2+1] - p[r2+1][c1] + p[r1][c1];

// Prefix sums + HashMap = "subarray sum equals k" in O(n)
int countSubarrays(int[] a, int k) {
    Map<Integer,Integer> seen = new HashMap<>();
    seen.put(0, 1);                                  // empty prefix
    int sum = 0, count = 0;
    for (int v : a) {
        sum += v;
        count += seen.getOrDefault(sum - k, 0);      // count earlier prefixes with sum − k
        seen.merge(sum, 1, Integer::sum);
    }
    return count;
}   // O(n) time · O(n) space
Signals that a problem wants prefix sums: “subarray/submatrix sum”, “range sum query”, “count subarrays where …”, “equal number of 0s and 1s” (map 0 → −1 first), “number of subarrays divisible by k” (store the running sum mod k).

5 The Collections framework

Choosing the right collection is the algorithm. This chapter is the selection map, the complexity table, and the API details that separate an accepted solution from a TLE.

Collections: choose, then code

Java's standard library gives you one implementation per shape: a growable array (ArrayList), a doubly-ended queue (ArrayDeque), a heap (PriorityQueue), hash and tree maps/sets, and a linked-order map. Learning which one to reach for takes an hour; it saves you from implementing heaps, balanced trees and hash tables by hand in every interview.

// Heap of long[] {dist, node} — Dijkstra's front end
PriorityQueue<long[]> pq = new PriorityQueue<>((x, y) -> Long.compare(x[0], y[0]));
pq.offer(new long[]{0, src});
long[] top = pq.poll();
long dist = top[0]; int node = (int) top[1];

// Heap of int[] {key, id} with a tie-break (never return 0 for distinct items!)
PriorityQueue<int[]> byScore = new PriorityQueue<>((p, q) ->
        p[0] != q[0] ? Integer.compare(p[0], q[0]) : Integer.compare(p[1], q[1]));

// K largest elements with an O(k) memory min-heap
int[] topK(int[] a, int k) {
    PriorityQueue<Integer> h = new PriorityQueue<>();
    for (int v : a) { h.offer(v); if (h.size() > k) h.poll(); }   // evict the smallest
    int[] out = new int[h.size()];
    for (int i = 0; i < out.length; i++) out[i] = h.poll();
    return out;
}   // O(n log k) time · O(k) space
FactWhy it matters
Iteration is not sorted orderOnly repeated poll() gives sorted output; use Arrays.sort if you just want order
contains/remove(Object) are O(n)Linear scan; a TreeSet is better if you need both a heap and membership
Comparator must be a total orderReturning a - b for large ints overflows; use Integer.compare
new PriorityQueue<>(collection) heapifies in O(n)Faster than n inserts when you already have all elements
Two-heap pattern (median)A max-heap of the lower half + a min-heap of the upper half, kept within size ±1 (ch. 13.9)

5.6 Iteration, modification, and ConcurrentModificationException

// ❌ This throws: structural modification during for-each
for (String k : map.keySet()) if (k.startsWith("x")) map.remove(k);   // ConcurrentModificationException

// ✅ 1 · Iterator (the classic interview-sanctioned way)
Iterator<String> it = map.keySet().iterator();
while (it.hasNext()) { if (it.next().startsWith("x")) it.remove(); }

// ✅ 2 · removeIf (Java 8+) — shortest and fastest to read
map.keySet().removeIf(k -> k.startsWith("x"));
list.removeIf(v -> v < 0);

// ✅ 3 · Collect first, mutate after
List<Integer> doomed = new ArrayList<>();
for (int v : list) if (v < 0) doomed.add(v);
list.removeAll(doomed);

// Iterating a map in the three useful ways
for (var e : map.entrySet()) { e.getKey(); e.getValue(); }            // var is Java 10+
for (String k : map.keySet()) { map.get(k); }                        // fine, one extra lookup
map.forEach((k, v) -> use(k, v));                                    // concise, callback per entry
Wrong assumptionReality
“I can remove while iterating with for-each”Never for ArrayList/HashMap/HashSet; only Iterator.remove() or removeIf are safe
“keySet() is a copy”It is a live view: removing from it removes from the map — convenient, and a bug source if you expected a snapshot
“subList is a copy”A view that writes through; copying needs new ArrayList<>(list.subList(a,b))
“Arrays.asList is an ArrayList”It is a fixed-size wrapper — add throws
“hashCode of an int[] works as a key”Arrays use identity hashing, so equal contents are different keys. Use List.of(...), a joined string, or a record wrapper

6 Sorting, searching & Comparators

In Java, “sort this the way I want” means “write a Comparator” — and a malformed Comparator is the single most common runtime crash in interview code.

Sorting and the Comparator contract

Arrays.sort, Collections.sort, list.sort, Comparator.comparing, Arrays.binarySearch and the PriorityQueue constructor all funnel through one concept: an ordering. Get the ordering right and half your solutions shrink to a line; get it wrong and you see IllegalArgumentException: Comparison method violates its general contract!.

Arrays.sort on primitives is not stable, and it uses quicksort — an adversary (or a TLE-obsessed test) cannot make it quadratic, but it also will not preserve the order of equal elements. If “equal keys in input order” matters, sort a boxed array/list, or sort indices with an index tie-break.

6.2 The Comparator contract — and how it crashes your code

// The six comparator shapes you actually need
Comparator<int[]> byFirst      = (p, q) -> Integer.compare(p[0], q[0]);
Comparator<int[]> bySecondDesc = (p, q) -> Integer.compare(q[1], p[1]);           // reversed
Comparator<int[]> byTwoKeys    = (p, q) -> p[0] != q[0] ? Integer.compare(p[0], q[0])
                                                        : Integer.compare(p[1], q[1]);
Comparator<String> byLength    = Comparator.comparingInt(String::length);
Comparator<int[]> bySum        = Comparator.comparingInt(r -> r[0] + r[1]);        // key extractor
Comparator<Integer> absOrder   = Comparator.comparingInt(Math::abs);

// Reverse any comparator without writing a new lambda
Comparator<int[]> byFirstDesc = byFirst.reversed();
// Null-safe
Comparator<String> nullsLast  = Comparator.nullsLast(Comparator.naturalOrder());

// Comparable on a custom class (so plain sort() works)
class Job implements Comparable<Job> {
    int start, end;
    Job(int s, int e) { start = s; end = e; }
    @Override public int compareTo(Job o) {
        if (start != o.start) return Integer.compare(start, o.start);
        return Integer.compare(end, o.end);
    }
}
// or, without touching the class:
List<Job> jobs = new ArrayList<>();
jobs.sort(Comparator.comparingInt((Job j) -> j.start).thenComparingInt(j -> j.end));
Interview style: prefer Comparator.comparingInt(...) to writing a lambda by hand — it is shorter, cannot overflow, and immediately documents the key. Annotate the lambda parameter type ((Job j) ->) when the compiler cannot infer it from the target type.

6.3 Binary search: the three templates

import java.util.function.IntPredicate;   // for the predicate-based templates below

// A · Exact search in a sorted ARRAY (returns index or -1)
int binarySearch(int[] a, int target) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;              // ✅ overflow-safe
        if (a[mid] == target) return mid;
        if (a[mid] < target) lo = mid + 1; else hi = mid - 1;
    }
    return -1;
}   // O(log n) time · O(1) space

// B · First index satisfying a monotone predicate ("leftmost true")
int lowerBound(int lo, int hi, IntPredicate ok) {  // [lo, hi] searchable range
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (ok.test(mid)) hi = mid; else lo = mid + 1;
    }
    return lo;
}

// C · Last index satisfying the predicate ("rightmost true")
int upperBound(int lo, int hi, IntPredicate ok) {
    while (lo < hi) {
        int mid = lo + (hi - lo + 1) / 2;          // ← the +1 avoids an infinite loop
        if (ok.test(mid)) lo = mid; else hi = mid - 1;
    }
    return lo;
}

// Examples of the predicate — the real skill
// smallest x with x*x >= n      : ok = mid -> (long) mid * mid >= n
// smallest capacity that ships  : ok = mid -> canShip(mid)
// leftmost insertion point for v: ok = mid -> a[mid] >= v
// real-valued answer (sqrt, rate): 200 iterations of the same loop with doubles
Recognising binary-search-on-answer problems: the phrasing says “minimise the maximum”, “maximise the minimum”, “smallest capacity/speed/days such that …”, or the answer is a number in a huge range with a cheap feasibility check. Constraints like n ≤ 105 with values up to 109 are a strong hint that O(n log V) is intended.

7.3 equals, hashCode — and why collections lie without them

// ❌ Without equals/hashCode, two “equal” objects are different keys
class Point { int x, y; Point(int x, int y) { this.x = x; this.y = y; } }
Set<Point> s = new HashSet<>();
s.add(new Point(1, 2));
s.contains(new Point(1, 2));        // false  ← identity comparison!

// ✅ Option A: a record — both methods are generated
record Point2(int x, int y) {}
new HashSet<Point2>().add(new Point2(1, 2));

// ✅ Option B: write them yourself (the contract: equal objects MUST have equal hash codes)
class P {
    final int x, y;
    P(int x, int y) { this.x = x; this.y = y; }
    @Override public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof P)) return false;
        P p = (P) o;
        return x == p.x && y == p.y;
    }
    @Override public int hashCode() { return 31 * x + y; }   // or Objects.hash(x, y)
    @Override public String toString() { return "(" + x + "," + y + ")"; }
}

List, Set, Map✅ (if elements are ✅)Structural equality; List.of(1,2) is a great composite key
int[], int[][], any array❌Arrays inherit identity hashing; wrap in List.of, a String key, or a record

8 Building blocks you will re-use

Union-Find, pairs, tries, integer encodings, quickselect and other small machines that appear inside dozens of different problems.

Paste-ready building blocks

Interviews reward recognition: the problem is usually a familiar structure wearing a story. These are the structures — Disjoint Set Union, a pair encoding, a trie, quickselect, a monotonic helper — each in the shortest correct Java form, ready to be adapted in place.

8.1 Disjoint Set Union (union-find)

class DSU {
    private final int[] parent, rank;
    private int components;

    DSU(int n) {
        parent = new int[n];
        rank = new int[n];
        components = n;
        for (int i = 0; i < n; i++) parent[i] = i;
    }

    int find(int x) {                       // path compression, iterative (no recursion depth risk)
        while (parent[x] != x) { parent[x] = parent[parent[x]]; x = parent[x]; }
        return x;
    }

    boolean union(int a, int b) {           // union by rank → O(α(n)) amortised
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;         // already connected: a cycle was found
        if (rank[ra] < rank[rb]) { int t = ra; ra = rb; rb = t; }
        parent[rb] = ra;
        if (rank[ra] == rank[rb]) rank[ra]++;
        components--;
        return true;
    }

    boolean connected(int a, int b) { return find(a) == find(b); }
    int count() { return components; }      // useful for “number of islands/provinces”
}
Signal in the statementWhy DSU
“connected components”, “provinces”, “friend circles”Union on each edge, then count roots
“would adding this edge create a cycle?” (Kruskal)union returns false exactly on a cycle
“grid cells connected 4-directionally”Map each cell to r * cols + c and union neighbours
“accounts merge”, “synonyms”, “equations”Union strings via a Map<String,Integer> id assignment
Grid DSU in one line: int id = r * cols + c;. Union right and down neighbours only — that covers all adjacency while visiting each pair once.

8.3 Trie (prefix tree)

class Trie {
    private final int[][] next = new int[100005][26];   // or a HashMap<Character,Integer> per node
    private final boolean[] end = new boolean[100005];
    private int nodes = 1;                              // node 0 is the root

    void insert(String w) {
        int cur = 0;
        for (int i = 0; i < w.length(); i++) {
            int c = w.charAt(i) - 'a';
            if (next[cur][c] == 0) next[cur][c] = nodes++;
            cur = next[cur][c];
        }
        end[cur] = true;
    }
    boolean contains(String w) {
        int cur = 0;
        for (int i = 0; i < w.length(); i++) {
            cur = next[cur][c(w, i)];
            if (cur == 0) return false;
        }
        return end[cur];
    }
    boolean startsWith(String p) {
        int cur = 0;
        for (int i = 0; i < p.length(); i++) {
            cur = next[cur][c(p, i)];
            if (cur == 0) return false;
        }
        return true;
    }
    private int c(String s, int i) { return s.charAt(i) - 'a'; }
}

// Object-node version — use when the alphabet is large or sparse (child maps instead of arrays)
class Node {
    Map<Character, Node> kids = new HashMap<>();
    boolean end;
}

int[N][26] arraysLowercase letters, up to ~105 nodesMemory 26 ints/node; fastest lookups
Map<Character,Node> per nodeMixed characters, few children eachObject-per-edge; slower but no wasted slots

8.4 Quickselect — O(n) average k-th element

// Median of an int array without a full sort (Lomuto partition)
int kth(int[] a, int k) {                    // k is 1-based: k = 1 gives the minimum
    int lo = 0, hi = a.length - 1, target = k - 1;
    java.util.Random rnd = new java.util.Random(42);
    while (true) {
        int p = lo + rnd.nextInt(hi - lo + 1);          // random pivot: avoids worst case on sorted input
        int t = a[p]; a[p] = a[hi]; a[hi] = t;
        int pivot = a[hi], i = lo;
        for (int j = lo; j < hi; j++) if (a[j] < pivot) { int tmp = a[i]; a[i] = a[j]; a[j] = tmp; i++; }
        int tmp = a[i]; a[i] = a[hi]; a[hi] = tmp;      // pivot to its final place: index i
        if (i == target) return a[i];
        if (i < target) lo = i + 1; else hi = i - 1;
    }
}   // O(n) average · O(n^2) worst case (randomisation makes it unlikely)
In interviews, Arrays.sort then a[k-1] is usually the right first answer (5 seconds of code, O(n log n)). Mention quickselect as the optimisation: “we can do it in expected O(n) with quickselect, which matters if the array is huge.” That sequence — simple first, then optimise — is exactly what the rubric rewards.

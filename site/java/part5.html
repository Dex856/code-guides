9 Memory, performance & the JVM

Java hides memory from you — until the judge hands back Memory Limit Exceeded or Time Limit Exceeded at the complexity you thought was fine.

Why Java is slower — and how to fix it

Every Java object carries an 8-byte header, every collection element is a reference, every Integer is a separate allocation, and int[][] is an array of pointers to arrays. None of that matters in business code and all of it matters at n = 106. This chapter is the cost model, the five hot-spot fixes, and how to estimate memory before you hit the limit.

The 30-second audit before submitting: (1) any boxed types inside the outermost loop? (2) any string concatenation? (3) any remove(0) or contains on a list? (4) any hash container that could be an array? (5) any recursion deeper than ~105? Fix them in that order — it matches the order they appear in profiles.

9.4 Threads, virtual threads, and why the judge does not care

LeetCode runs your method on one thread, once per test case. Concurrency tools are relevant in system-design rounds and production code, not in an algorithm submission. One paragraph, so you are not caught out if it comes up:

ConceptOne-line reality
Thread / ExecutorServiceOS-backed threads, ~1 MB stack each — parallelism for CPU-bound work
ConcurrentHashMap, AtomicIntegerLock-free/synchronised structures for sharing state between threads
Virtual threads (Java 21+)Millions of cheap threads for blocking I/O; still not useful for a CPU-bound algorithm
synchronized / volatileMutual exclusion / visibility; in LeetCode they only slow you down
If an interviewer asks “how would you parallelise this?” the expected answer is about partitioning the input (split the array, merge partial results), not about syntax. Mention Arrays.parallelSort and parallel streams as the built-in forms, then note that for n ≤ 106 the single-threaded version is already fast enough that coordination would dominate.

// Rolling rows: 0/1 knapsack in O(capacity) memory instead of O(n × capacity)
int knapsack(int[] w, int[] v, int cap) {
    int[] dp = new int[cap + 1];
    for (int i = 0; i < w.length; i++)
        for (int c = cap; c >= w[i]; c--)              // ⚠ downward: each item used once
            dp[c] = Math.max(dp[c], dp[c - w[i]] + v[i]);
    return dp[cap];
}
// Unbounded knapsack (coin change): the SAME loop, direction UP
// for (int c = w[i]; c <= cap; c++) dp[c] = Math.max(dp[c], dp[c - w[i]] + v[i]);
The direction of that inner loop is the whole difference between “use each item once” and “use each item any number of times”. Write the loop variable, then ask: when I read dp[c - w[i]], do I want the value from before this item or after?

10 Bits & modular arithmetic

Bit tricks turn O(n) space into O(1); modular arithmetic turns “the answer is astronomically large” into “compute it mod 109+7”.

Bits, sets and modular math

Two families of tricks that appear in every interview cycle: bit manipulation (XOR, masks, subsets) and number theory under a modulus (powers, inverses, combinations, sieves). Both are memorisable in an afternoon and are individually worth several problems in the bank.

// XOR identities (the source of every “find the single number” problem):
//     x ^ x == 0        x ^ 0 == x        a ^ b ^ a == b
// 1 · one element appears once, all others twice
int single = 0; for (int v : a) single ^= v;

// 2 · two elements appear once (all others twice): split by a differing bit
int xr = 0; for (int v : a) xr ^= v;
int low = xr & -xr;                       // lowest bit where the two singles differ
int g1 = 0, g2 = 0;
for (int v : a) { if ((v & low) != 0) g1 ^= v; else g2 ^= v; }

// 3 · the third number appears once among triples: count bits mod 3
int once = 0;
for (int b = 0; b < 32; b++) {
    int cnt = 0;
    for (int v : a) cnt += (v >> b) & 1;
    if (cnt % 3 != 0) once |= (1 << b);
}

// 4 · power of two, and the next power of two
boolean isPow2 = x > 0 && (x & (x - 1)) == 0;
int highest = Integer.highestOneBit(x);
int nextPow2 = Integer.highestOneBit(x) << 1;   // (x is already a power of two)
int minPow2 = Integer.MAX_VALUE - Integer.numberOfLeadingZeros(x) >> 27;  // arithmetic-free variant
Fastest power-of-two check for arrays: capacity 8, 16, 32… lets you replace i % n with i & (n - 1). Java's own HashMap does exactly this.

10.2 Subsets, masks and bitmask DP

// Iterate all 2^n subsets of n elements (n ≤ 20 in practice)
for (int mask = 0; mask < (1 << n); mask++) {
    for (int i = 0; i < n; i++)
        if ((mask & (1 << i)) != 0) { /* element i is in this subset */ }
}
int size = Integer.bitCount(mask);                 // Cardinality in O(1)

// Iterate the submasks of a given mask (total 3^n over all masks — n ≤ 15–18)
for (int sub = mask; sub > 0; sub = (sub - 1) & mask) { /* proper non-empty subset */ }

// Set algebra on masks
int union = a | b, inter = a & b, diff = a & ~b;
boolean subset = (a & b) == a;                    // a ⊆ b

// Bitmask DP: dp[mask] = best value using exactly the elements in mask
int[] dp = new int[1 << n];
Arrays.fill(dp, Integer.MAX_VALUE);
dp[0] = 0;
for (int mask = 0; mask < (1 << n); mask++) {
    if (dp[mask] == Integer.MAX_VALUE) continue;
    for (int i = 0; i < n; i++) {
        if ((mask & (1 << i)) != 0) continue;     // already used
        int next = mask | (1 << i);
        dp[next] = Math.min(dp[next], dp[mask] + cost[i]);   // adapt the transition
    }
}
// answer is typically dp[(1 << n) - 1]
Choosing the state encoding. A long holds 63 usable bits; a state needing more than 20–22 items as a plain mask becomes memory-hostile (2n entries). When n ≥ 25, look for a different structure — greedy, matching, or interval DP.

10.3 Primes: sieve and factorisation

// Sieve of Eratosthenes — all primes below n, O(n log log n)
boolean[] isComposite = new boolean[n];
for (int p = 2; (long) p * p < n; p++)                  // ⚠ the cast prevents overflow
    if (!isComposite[p])
        for (int m = p * p; m < n; m += p) isComposite[m] = true;

// Trial division for one number — O(sqrt n)
boolean isPrime(long x) {
    if (x < 2) return false;
    for (long d = 2; d * d <= x; d++) if (x % d == 0) return false;
    return true;
}

// Smallest-prime-factor sieve: factorise any x ≤ n in O(log x)
int[] spf = new int[n + 1];
for (int i = 2; i <= n; i++) if (spf[i] == 0)
    for (int j = i; j <= n; j += i) if (spf[j] == 0) spf[j] = i;

List<Integer> factorise(int x, int[] spf) {
    List<Integer> out = new ArrayList<>();
    while (x > 1) { out.add(spf[x]); x /= spf[x]; }
    return out;
}

// Greatest common divisor / least common multiple
int gcd(int a, int b) { while (b != 0) { int t = a % b; a = b; b = t; } return a; }  // Euclid
long lcm(long a, long b) { return a / gcd((int) a, (int) b) * b; }                  // divide FIRST

// Count divisors by trial division: for (d = 1; d*d <= x; d++) if (x % d == 0) cnt += (d*d == x ? 1 : 2);

10.4 Modular arithmetic — the “answer mod 109+7” drill

static final long MOD = 1_000_000_007L;

long add(long a, long b) { return (a + b) % MOD; }
long sub(long a, long b) { return (a - b % MOD + MOD) % MOD; }        // ⚠ negatives
long mul(long a, long b) { return (a * b) % MOD; }                   // a,b < 1e9 → product < 1e18 ✅ fits in long

long pow(long base, long exp) {                                       // fast exponentiation O(log exp)
    long r = 1; base %= MOD;
    while (exp > 0) {
        if ((exp & 1) == 1) r = r * base % MOD;
        base = base * base % MOD;
        exp >>= 1;
    }
    return r;
}

long modInverse(long a) {                                             // Fermat: a^(p−2) when p is prime
    return pow(a, MOD - 2);
}
long divide(long a, long b) { return a % MOD * modInverse(b) % MOD; } // “division” under a prime modulus

// nCr mod p with factorials (precompute once: O(n))
long[] fact, invFact;
void precompute(int n) {
    fact = new long[n + 1]; invFact = new long[n + 1];
    fact[0] = 1;
    for (int i = 1; i <= n; i++) fact[i] = fact[i - 1] * i % MOD;
    invFact[n] = modInverse(fact[n]);
    for (int i = n; i > 0; i--) invFact[i - 1] = invFact[i] * i % MOD;
}
long nCr(int n, int r) {
    if (r < 0 || r > n) return 0;
    return fact[n] * invFact[r] % MOD * invFact[n - r] % MOD;
}
Modulo is not distributable over subtraction in Java. (a - b) % MOD can be negative. Always ((a - b) % MOD + MOD) % MOD. The same applies to accumulating differences and to hash-code-style keys.

10.5 Geometry without floating point

// Prefer integer arithmetic: exact answers, no epsilon decisions
long cross(int ax, int ay, int bx, int by, int cx, int cy) {   // (b−a) × (c−a)
    return (long) (bx - ax) * (cy - ay) - (long) (by - ay) * (cx - ax);
}
// cross > 0 → c is left of a→b · cross < 0 → right · == 0 → collinear
boolean onSegment(int ax, int ay, int bx, int by, int px, int py) {
    return cross(ax, ay, bx, by, px, py) == 0
        && Math.min(ax, bx) <= px && px <= Math.max(ax, bx)
        && Math.min(ay, by) <= py && py <= Math.max(ay, by);
}
long sqDist(int ax, int ay, int bx, int by) {                  // compare squared distances
    long dx = ax - bx, dy = ay - by;  return dx * dx + dy * dy;   // no sqrt needed for comparisons
}
double dist(int ax, int ay, int bx, int by) {
    return Math.hypot((double) ax - bx, (double) ay - by);
}

11.2 Reading a problem in 60 seconds

  1. Restate it in one sentence with the input/output types. If you cannot, you have not understood it yet.
  2. Write the smallest example by hand and solve it manually. The manual steps are the algorithm’s first draft.
  3. Read the constraints and pick the intended complexity from the table in ch. 14.1. This single step rules out most wrong approaches.
  4. Find the pattern in the table above — the phrasing “contiguous”, “k-th”, “number of ways”, “shortest” maps directly.
  5. Check the edge cases before coding: empty input, single element, all equal, negatives, duplicates, maximum size.
  6. State the plan out loud (or in a comment) in ≤ 2 sentences, then write the code.
The interview scoring order is: clarify → approach → code → complexity → test. Skipping the first two to “save time” is the most common way to fail an otherwise solvable problem, because the interviewer is scoring the reasoning, not the typing.

1 Setup, compilation and the LeetCode workflow

From a blank file to a running solution: the compiler flags that catch bugs early, and a local test loop.

1.1 Compile and run in one command

# Single file, LeetCode-style solution + your own main()
g++ -std=c++20 -O2 -Wall -Wextra -o sol sol.cpp && ./sol

# The flags that matter
#   -std=c++17|c++20|c++23   choose the standard (LeetCode uses C++17 by default)
#   -O2                      optimise (judge uses -O2); use -O0 for readable debug info
#   -g                       debug symbols (gdb)
#   -Wall -Wextra            warnings = free bug detection
#   -fsanitize=address,undefined   catch out-of-bounds, overflow, UB in tests! (dev only)
#   -D_GLIBCXX_DEBUG         checked STL iterators (catches invalid iterator use)

g++ -std=c++20 -O1 -g -fsanitize=address,undefined sol.cpp -o sol_dbg && ./sol_dbg

# Windows: MSVC via Developer Prompt
#   cl /std:c++20 /EHsc /O2 sol.cpp
# macOS: clang++ -std=c++20 -O2 sol.cpp -o sol
# Fast input for competitive-style problems
#   ios::sync_with_stdio(false); cin.tie(nullptr);
Use sanitizers locally, never on the judge. A 3-second run under -fsanitize=address,undefined finds the out-of-bounds write that would otherwise show up as a mysterious Wrong Answer at test 200. This is the single highest-value habit in this chapter.

1.2 The LeetCode skeleton you actually write

#include <bits/stdc++.h>      // GCC/Clang convenience header used by most competitive C++
using namespace std;

class Solution {
public:
    long long total(const vector<int>& nums) const {   // const& = read-only, no copy
        long long s = 0;                                  // accumulate in 64-bit
        for (int x : nums) s += x;
        return s;
    }
};

#ifdef LOCAL_TEST                       // only compiled when you ask for it
int main() {
    vector<int> v{1, 2, 3};
    cout << Solution().total(v) << '\n';   // 6
    assert(Solution().total({}) == 0);
    cout << "OK\n";
}
#endif
// compile with:  g++ -std=c++20 -O2 -DLOCAL_TEST sol.cpp -o sol
Why <bits/stdc++.h>? It is a GCC header that pulls in the whole standard library — perfect for contests, useless in production (it is non-portable and slows compile times). Know how to write explicit includes too: <vector> <string> <unordered_map> <algorithm> <queue> <numeric> <climits>.

1.4 Local test loop that catches real bugs

// Three levels of testing, in increasing power:
// 1) assert on the examples          2) random stress vs brute force         3) sanitizers

#include <bits/stdc++.h>
using namespace std;

// ---- level 2: stress test -------------------------------------------------
int solveFast(const vector<int>& a);           // your optimised solution
int solveBrute(const vector<int>& a);          // obviously-correct slow version

int main() {
    mt19937 rng(12345);                        // fixed seed = reproducible
    uniform_int_distribution<int> nDist(1, 8), vDist(-5, 5);
    for (int iter = 0; iter < 20000; ++iter) {
        int n = nDist(rng);
        vector<int> a(n);
        for (int& x : a) x = vDist(rng);
        int f = solveFast(a), b = solveBrute(a);
        if (f != b) {
            cout << "MISMATCH on: ";
            for (int x : a) cout << x << ' ';
            cout << "\nfast=" << f << " brute=" << b << '\n';
            return 1;
        }
    }
    cout << "all random tests passed\n";       // then compile with sanitizers
}
The stress-test habit: write the brute force first, then optimise. Twenty thousand random cases under sanitizers finds essentially every indexing and overflow bug in minutes — it is faster than staring at code, and it is how experienced contestants avoid re-submitting 6 times.

2 Types, references and the overflow trap

C++ is statically typed; most wrong answers come from the type you chose, not the algorithm you wrote.

2.1 The types you need (and nothing else)

TypeBytes (typical)RangeUse for
int4±2.147·10⁹default integer; indices, counts up to 2·10⁹
long long8±9.22·10¹⁸any sum/product that can overflow int; distances; modular math
unsigned40 … 4.29·10⁹bit tricks only — never for subtraction-heavy logic
double8~15–17 significant digitsgeometry, averages, sqrt; compare with epsilon
long double12–16~18 digitsrarely needed; avoid relying on it
char1−128…127 / 0…255single characters; arithmetic on ASCII
bool1true / falseflags; vector<bool> is special (ch. 12)
size_t8 (64-bit)0 … 2⁶⁴−1what .size() returns — unsigned!
 
#include <bits/stdc++.h>
using namespace std;
using ll = long long;                 // the alias you will type a thousand times
const int INF = 1e9;                  // "infinity" for int-based graphs
const ll  LINF = 4e18;                // "infinity" for long long

const int MOD = 1'000'000'007;        // digit separators are legal C++14+

int main() {
    int a = 1e9, b = 1e9;
    // int c = a + b;                  // UB (signed overflow) → garbage or wrap
    long long c = 1LL * a + b;         // 2e9, correct

    // The three ways overflow sneaks in:
    // 1) multiplication before promotion
    int x = 100000, y = 100000;
    // int bad = x * y;                // overflow happens in int, BEFORE assignment
    long long good = 1LL * x * y;      // promote one operand to 64-bit first

    // 2) accumulate defaults to the container's type
    vector<int> v(1e5, 1e6);
    // long long wrong = accumulate(v.begin(), v.end(), 0);      // sums in int!
    long long right = accumulate(v.begin(), v.end(), 0LL);       // 0LL forces 64-bit

    // 3) mod arithmetic with negative results
    // (a - b) % MOD can be negative → ((a - b) % MOD + MOD) % MOD
    return 0;
}

2.2 Values, references and pointers — the memory picture

void byValue(vector<int> v)        { v.push_back(4); }   // caller unchanged; copied
void byRef(vector<int>& v)         { v.push_back(4); }   // caller CHANGED
void byConstRef(const vector<int>& v) { /* read only */ }  // caller unchanged, no copy

vector<int> a{1,2,3};
byValue(a);   // a = {1,2,3}
byRef(a);     // a = {1,2,3,4}

// auto, structured bindings, and const correctness
auto n = a.size();                      // size_t (unsigned!)
auto [lo, hi] = pair{1, 2};             // structured binding (C++17)
for (const auto& [k, val] : mapOfStuff) { /* no copy, no mutation */ }
for (auto& x : a) x *= 2;               // mutate in place without indices

// constexpr / const
const double PI = 3.141592653589793;
constexpr int SZ = 1000;                // compile-time constant: usable for array sizes

// Type conversion rules that bite
int   i = 7;     double d = i / 2;      // 3.0  ← integer division first!
double e = i / 2.0;                     // 3.5
char  c = '7';   int  digit = c - '0';  // 7    ← the standard char→digit trick
int   z = c;                            // 55   ← ASCII code, not the digit

2.3 Operators, integer division, and comparison gotchas

7 / 2        //  3   (integer division truncates toward zero)
-7 / 2       // -3   ← C++ truncates; Python floors to -4. Different answers!
-7 % 2       // -1   ← C++ remainder keeps the sign of the dividend
7 % 2        //  1
// Floor division & positive modulo, the safe versions:
int floordiv(int a, int b) { return (a - (a % b + b) % b) / b; }
int mod(int a, int m)      { return ((a % m) + m) % m; }

// Comparison and boolean ops
a == b   a != b   a < b   a <= b
a && b   a || b   !a            // short-circuit: b is not evaluated if a decides it
x ? y : z                       // ternary
// Bitwise (ch. 10): a & b   a | b   a ^ b   ~a   a << k   a >> k

// The classic pitfall: mixing signed and unsigned
vector<int> v{1,2,3};
// for (int i = 0; i < v.size(); ++i)      // warning: signed/unsigned comparison
for (size_t i = 0; i < v.size(); ++i)      // clean
for (int i = 0; i < (int)v.size(); ++i)    // or cast (fine for n < 2^31)
for (size_t i = 0; i + 1 < v.size(); ++i)  // the idiom that avoids v[i+1] overrun

// Comparing doubles: never ==
bool close(double a, double b, double eps = 1e-9) { return fabs(a - b) < eps; }
Subscript with a negative index is UB, not an exception. C++ has no bounds checking on v[i]. v.at(i) throws and is the debugging variant — use it while developing, and use -D_GLIBCXX_DEBUG or ASan to catch the rest.

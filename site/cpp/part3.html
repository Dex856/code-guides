6 Algorithms: sort, binary search, and the rest of <algorithm>

Fifteen standard algorithms replace a hundred lines of hand-written loops — and they are faster and already correct.

Predicates and comparators return bool: “is x before y?”. Returning anything that is not a strict weak ordering (for example x <= y) is undefined behaviour inside sort — it can even crash with an out-of-bounds write, because the algorithm relies on the ordering to bound itself.

6.2 Binary search: three functions and one template

// ---- lower_bound / upper_bound on sorted containers ---------------------
vector<int> a{1, 2, 4, 4, 4, 7, 9, 10};
int lb = lower_bound(a.begin(), a.end(), 4) - a.begin();     // 2
int ub = upper_bound(a.begin(), a.end(), 4) - a.begin();     // 5
int copies = ub - lb;                                        // 3
bool has5 = binary_search(a.begin(), a.end(), 5);            // false

// set / map have their own member versions (O(log n), no linear iterator math)
set<int> s{1, 4, 9};
auto it = s.lower_bound(4);          // member: same name, faster than std::lower_bound on a set

// ---- BINARY SEARCH ON THE ANSWER (the highest-value pattern) ------------
// Use when: "minimise the maximum", "maximise the minimum", "find the smallest
// value such that a monotonic condition holds". Write the feasibility check first!
//
// Example shape: split array into m parts minimising the largest sum.
bool feasible(const vector<int>& a, int m, long long cap) {
    int parts = 1; long long cur = 0;
    for (int x : a) {
        if (cur + x > cap) { ++parts; cur = 0; }
        cur += x;
    }
    return parts <= m;
}
long long minLargestSum(vector<int>& a, int m) {
    long long lo = *max_element(a.begin(), a.end());     // feasibility bound
    long long hi = accumulate(a.begin(), a.end(), 0LL);
    while (lo < hi) {
        long long mid = lo + (hi - lo) / 2;              // ← never (lo+hi)/2 (overflow)
        if (feasible(a, m, mid)) hi = mid; else lo = mid + 1;
    }
    return lo;
}

// ---- Binary search over reals (fixed 60–100 iterations, no epsilon loop) --
double solve(double lo, double hi) {
    for (int iter = 0; iter < 80; ++iter) {
        double mid = (lo + hi) / 2;
        if (ok(mid)) hi = mid; else lo = mid;
    }
    return lo;
}

// ---- Searching in a rotated sorted array (classic twist) -----------------
int searchRotated(vector<int>& a, int target) {
    int lo = 0, hi = a.size() - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] == target) return mid;
        if (a[lo] <= a[mid]) {                            // left half sorted
            if (a[lo] <= target && target < a[mid]) hi = mid - 1; else lo = mid + 1;
        } else {                                          // right half sorted
            if (a[mid] < target && target <= a[hi]) lo = mid + 1; else hi = mid - 1;
        }
    }
    return -1;
}
Overflow in binary search: (lo + hi) / 2 overflows when both are near 10¹⁸. Always write lo + (hi - lo) / 2. And use long long for the bounds in answer-search problems even when the array is int — caps are usually sums.

7.1 Lambdas

// [capture](parameters) -> return_type { body }

// The recursive lambda idiom (DFS in 4 lines, no helper function needed)
auto dfs = [&](auto&& self, int u, int parent) -> void {
    visited[u] = true;
    for (int v : adj[u]) if (v != parent) self(self, v, u);
};
dfs(dfs, 0, -1);                                   // C++14 generic lambda + explicit self

// Alternative for recursion when you want the classic signature:
function<void(int,int)> dfs2 = [&](int u, int p) {
    for (int v : adj[u]) if (v != p) dfs2(v, u);
};
dfs2(0, -1);                                       // std::function: convenient, slower

// Immediately-invoked lambda for scoping
int answer = [&] { /* compute */ return 42; }();
Which recursion style for interviews? Use the auto&& self generic lambda (zero overhead) or plain member functions of Solution (what most published solutions use). std::function is the readable but slowest option — it type-erases and blocks inlining; at depth 10⁵ it can be 3–10× slower.

7.2 Comparators — the rules, and the patterns

struct Point { int x, y; };

// 1 · sort by one field
sort(v.begin(), v.end(), [](const Point& a, const Point& b){ return a.x < b.x; });

// 2 · multi-key: x ascending, then y descending
sort(v.begin(), v.end(), [](const Point& a, const Point& b){
    if (a.x != b.x) return a.x < b.x;      // primary key
    return a.y > b.y;                      // secondary key
});

// 3 · pairs sort lexicographically for free — pack keys into a pair/tuple
vector<pair<int,int>> p;                  // sorts by .first, then .second
vector<tuple<int,int,int>> t;             // sorts by element order
sort(t.begin(), t.end());                  // works out of the box
// To sort by (score desc, index asc) without a comparator:
vector<pair<int,int>> keys;               // {-score, index}
sort(keys.begin(), keys.end());

// 4 · sort indices instead of values (keeps the original array intact)
vector<int> idx(n); iota(idx.begin(), idx.end(), 0);
sort(idx.begin(), idx.end(), [&a](int i, int j){ return a[i] < a[j]; });

// 5 · min-heap / max-heap comparators
priority_queue<int, vector<int>, greater<int>> minHeap;
auto cmp = [](const Point& a, const Point& b){ return a.x > b.x; };   // min by x on top
priority_queue<Point, vector<Point>, decltype(cmp)> pq(cmp);

// 6 · sorting structs with operator< defined (no comparator needed anywhere)
struct Task {
    int priority, id;
    bool operator<(const Task& o) const { return priority < o.priority; }
};
sort(tasks.begin(), tasks.end());          // uses operator<
// ordered containers also need equality/less ONLY (set/map do not use ==)
Two comparator bugs that are invisible in tests: (1) comparing floating point with < is fine, but == on doubles is not — sort keys should be integers or exact comparisons. (2) a comparator that captures by reference and reads a container you then modify during the sort gives non-deterministic results. Sort a copy, or precompute the keys.

8 Structs, operators, and the LeetCode node types

Classes exist in interview C++ mainly for one reason: giving custom types a sorting order, a hash, or a heap priority.

8.1 struct, operator overloading, and why it matters

struct Job {
    int start, end, profit;
    // Sorting: define ONE order once, use it everywhere (sort, set, priority_queue)
    bool operator<(const Job& o) const {
        if (end != o.end) return end < o.end;
        return start < o.start;
    }
    bool operator==(const Job& o) const { return start == o.start && end == o.end; }
};
vector<Job> jobs;  sort(jobs.begin(), jobs.end());          // uses operator<

// Arithmetic-style operator for coordinates / fractions
struct Vec {
    long long x, y;
    Vec operator+(const Vec& o) const { return {x + o.x, y + o.y}; }
    Vec operator-(const Vec& o) const { return {x - o.x, y - o.y}; }
    long long dot(const Vec& o) const { return x*o.x + y*o.y; }
    long long cross(const Vec& o) const { return x*o.y - y*o.x; }   // sign = turn direction
};
// cross > 0 → counter-clockwise; == 0 → collinear. The basis of geometry problems.

// Stream operator is handy for debugging (not needed on the judge)
struct Node { int id, w; };
ostream& operator<<(ostream& os, const Node& n) { return os << "(" << n.id << "," << n.w << ")"; }

// Constructors, default values, methods
struct DSU {
    vector<int> p, r;
    DSU(int n) : p(n), r(n, 0) { iota(p.begin(), p.end(), 0); }   // init list
    int find(int x) { return p[x] == x ? x : p[x] = find(p[x]); } // path compression
    bool unite(int a, int b) {
        a = find(a); b = find(b);
        if (a == b) return false;
        if (r[a] < r[b]) swap(a, b);
        p[b] = a; if (r[a] == r[b]) ++r[a];                        // union by rank
        return true;
    }
};
// struct = class with public members by default. That is the entire difference.

8.2 LeetCode’s ListNode and TreeNode — the exact code you need

// Provided by LeetCode (do NOT redefine these when submitting):
struct ListNode {
    int val;
    ListNode *next;
    ListNode() : val(0), next(nullptr) {}
    ListNode(int x) : val(x), next(nullptr) {}
    ListNode(int x, ListNode *next) : val(x), next(next) {}
};
struct TreeNode {
    int val;
    TreeNode *left;
    TreeNode *right;
    TreeNode() : val(0), left(nullptr), right(nullptr) {}
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
    TreeNode(int x, TreeNode *l, TreeNode *r) : val(x), left(l), right(r) {}
};

// ---------- linked list: reverse (iterative) ----------
ListNode* reverseList(ListNode* head) {
    ListNode* prev = nullptr;
    while (head) {
        ListNode* nxt = head->next;      // save
        head->next = prev;               // flip
        prev = head;                     // advance
        head = nxt;
    }
    return prev;                         // new head
}
// ---------- linked list: reverse (recursive) ----------
ListNode* reverseRec(ListNode* head) {
    if (!head || !head->next) return head;
    ListNode* newHead = reverseRec(head->next);
    head->next->next = head;
    head->next = nullptr;
    return newHead;
}
// ---------- cycle detection: Floyd (two pointers) ----------
bool hasCycle(ListNode* head) {
    ListNode *slow = head, *fast = head;
    while (fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) return true;
    }
    return false;
}
// ---------- find middle (slow/fast) ----------
ListNode* middle(ListNode* head) {
    ListNode *slow = head, *fast = head;
    while (fast && fast->next) { slow = slow->next; fast = fast->next->next; }
    return slow;
}
// ---------- dummy-head merging (never special-case the first node) --------
ListNode* mergeTwo(ListNode* a, ListNode* b) {
    ListNode dummy(0), *tail = &dummy;          // stack dummy: fine, return dummy.next
    while (a && b) {
        if (a->val <= b->val) { tail->next = a; a = a->next; }
        else                 { tail->next = b; b = b->next; }
        tail = tail->next;
    }
    tail->next = a ? a : b;
    return dummy.next;
}

// ---------- tree traversals ----------
void preorder(TreeNode* r, vector<int>& out)  { if (!r) return; out.push_back(r->val); preorder(r->left,out); preorder(r->right,out); }
void inorder(TreeNode* r, vector<int>& out)   { if (!r) return; inorder(r->left,out); out.push_back(r->val); inorder(r->right,out); }
void postorder(TreeNode* r, vector<int>& out) { if (!r) return; postorder(r->left,out); postorder(r->right,out); out.push_back(r->val); }

// Iterative inorder (needed when recursion depth is a problem)
vector<int> inorderIt(TreeNode* root) {
    vector<int> out; stack<TreeNode*> st; TreeNode* cur = root;
    while (cur || !st.empty()) {
        while (cur) { st.push(cur); cur = cur->left; }
        cur = st.top(); st.pop();
        out.push_back(cur->val);
        cur = cur->right;
    }
    return out;
}

// Level-order with a queue, level by level
vector<vector<int>> levelOrder(TreeNode* root) {
    vector<vector<int>> res; if (!root) return res;
    queue<TreeNode*> q; q.push(root);
    while (!q.empty()) {
        int sz = q.size(); vector<int> level;
        while (sz--) {
            TreeNode* n = q.front(); q.pop();
            level.push_back(n->val);
            if (n->left)  q.push(n->left);
            if (n->right) q.push(n->right);
        }
        res.push_back(level);
    }
    return res;
}
// Depth / height, and validating a BST
int depth(TreeNode* r) { return r ? 1 + max(depth(r->left), depth(r->right)) : 0; }
bool isBST(TreeNode* r, long long lo = LLONG_MIN, long long hi = LLONG_MAX) {
    if (!r) return true;
    if (r->val <= lo || r->val >= hi) return false;      // long long bounds avoid INT_ edge cases
    return isBST(r->left, lo, r->val) && isBST(r->right, r->val, hi);
}
Pointer habits for tree/list problems: check nullptr before dereferencing (if (!node) return ...); use a local long long range when validating BSTs to dodge INT_MIN/INT_MAX edge cases; prefer a stack-based traversal if depth may exceed ~10⁴ (no C++ recursion limit, but the C stack can still overflow); and remember LeetCode nodes are heap-allocated — never delete them, and never return a pointer to a local.

8.3 Custom hash for unordered containers (anti-hack)

// The problem: unordered_set<int> with keys like 107897 hashes poorly and degrades to O(n)
// per operation → TLE on LeetCode's anti-hash tests. Fix: a randomized 64-bit mixer.

struct custom_hash {
    static uint64_t splitmix64(uint64_t x) {
        x += 0x9e3779b97f4a7c15ULL;
        x = (x ^ (x >> 30)) * 0xbf58476d1ce4e5b9ULL;
        x = (x ^ (x >> 27)) * 0x94d049bb133111ebULL;
        return x ^ (x >> 31);
    }
    size_t operator()(uint64_t x) const {
        static const uint64_t FIXED_RANDOM =
            chrono::steady_clock::now().time_since_epoch().count();
        return splitmix64(x + FIXED_RANDOM);
    }
};

unordered_map<long long, int, custom_hash> safe;
unordered_set<long long, custom_hash> safeSet;

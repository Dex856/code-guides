0.3 The LeetCode Java environment in 60 seconds

LeetCode compiles your submission as a single Solution class (Java 25 on the judge) with the common java.util.* classes already imported, so you can type ArrayList<Integer> or Map.Entry<K,V> without adding imports. There is no main: your method is called once per test case on the same class instance.

// What LeetCode runs for "Two Sum" — the skeleton you fill in
class Solution {
    public int[] twoSum(int[] nums, int target) {
        Map<Integer, Integer> seen = new HashMap<>();   // java.util.* is pre-imported on the judge
        for (int i = 0; i < nums.length; i++) {
            int need = target - nums[i];
            if (seen.containsKey(need)) return new int[]{seen.get(need), i};
            seen.put(nums[i], i);
        }
        return new int[]{-1, -1};                        // never reached for valid input
    }
}   // O(n) time · O(n) space
Three consequences of the judge model — all covered later, all real:
  • Fields persist across test cases. A static or instance field you “reset by intuition” is re-used for the next case. Declare state inside the method (ch. 12.5).
  • No main, no printing. Debugging means the local harness in 1.3 — printing inside a solution is the slowest way to fail.
  • Signatures are fixed. You cannot change the return type to long; convert inside (ch. 2.2).

1.2 The local harness shape

LeetCode gives you a bare method with no main. Locally, wrap it yourself: keep the Solution class byte-for-byte identical to what you submit, and put all testing in a separate class so nothing you add for debugging can leak into the submission.

// ---------------- Sol.java — the part you paste into LeetCode ----------------
class Solution {
    public int[] twoSum(int[] nums, int target) {
        java.util.Map<Integer, Integer> seen = new java.util.HashMap<>();
        for (int i = 0; i < nums.length; i++) {
            int need = target - nums[i];
            if (seen.containsKey(need)) return new int[]{seen.get(need), i};
            seen.put(nums[i], i);
        }
        return new int[0];
    }
}

// ---------------- Main.java — local only, never submitted --------------------
public class Main {
    public static void main(String[] args) {
        Solution s = new Solution();
        check(java.util.Arrays.equals(s.twoSum(new int[]{2, 7, 11, 15}, 9), new int[]{0, 1}));
        check(java.util.Arrays.equals(s.twoSum(new int[]{3, 2, 4}, 6),        new int[]{1, 2}));
        check(java.util.Arrays.equals(s.twoSum(new int[]{3, 3}, 6),           new int[]{0, 1}));
        System.out.println("all asserts passed");
    }
    // assert() is disabled unless -ea is passed, so use an explicit helper instead
    static void check(boolean ok) { if (!ok) throw new AssertionError("failed"); }
}
Trap: assert x == 4; does nothing by default — Java disables assertions unless you run with java -ea. Use an explicit check(...) helper (above) or always pass -ea.

1.3 The 3-level test loop

LevelWhat you writeWhat it catches
1 · ExamplesEvery sample from the problem statement, plus the empty and size-1 cases. Wrong output on the happy path; null/empty handling; off-by-one on the last element.
2 · Brute force + random stressA slow-but-obviously-correct method, then 1,000 random small inputs comparing both outputs.Everything subtle: boundary conditions, duplicate handling, tie-breaking, overflow on small-but-nasty values.
3 · Scale & safetyOne max-size random input with a stopwatch; then re-run the samples after changing nothing.TLE (wrong complexity), StackOverflowError, quadratic hidden inside a loop, and accidental reliance on test order from leftover fields.
 
// Level 2: randomised stress test — the highest-value 20 lines you will ever write
static void stress() {
    java.util.Random rnd = new java.util.Random(12345);      // fixed seed -> reproducible
    Solution s = new Solution();
    for (int t = 0; t < 1000; t++) {
        int n = 1 + rnd.nextInt(8);
        int[] a = new int[n];
        for (int i = 0; i < n; i++) a[i] = rnd.nextInt(21) - 10;   // includes negatives
        int target = rnd.nextInt(41) - 20;
        int[] fast = s.twoSum(a, target), slow = brute(a, target);
        if (fast.length != slow.length || (fast.length == 2 &&
            !(fast[0] == slow[0] && fast[1] == slow[1]))) {
            System.out.println("MISMATCH on " + java.util.Arrays.toString(a) + " target=" + target);
            System.out.println("fast=" + java.util.Arrays.toString(fast) + " slow=" + java.util.Arrays.toString(slow));
            return;
        }
    }
    System.out.println("stress passed");
}
static int[] brute(int[] a, int t) {                          // O(n^2), obviously correct
    for (int i = 0; i < a.length; i++)
        for (int j = i + 1; j < a.length; j++)
            if (a[i] + a[j] == t) return new int[]{i, j};
    return new int[0];
}
Randomise values, not just sizes. Negative numbers, zero, duplicates, and the extreme of the allowed range expose more bugs than 10,000 well-behaved cases. Generate values in [-10, 10] first; if that passes, widen to the real constraints.

2 Types, numbers, boxing

The number-one source of wrong answer in Java submissions is not the algorithm — it is an int that overflowed, an Integer compared with ==, or a NULL that got unboxed.

Types & numbers without landmines

Java has two parallel worlds — primitives (int, long, char, double…) and reference types (Integer, Long, Character…). Collections only store the second world, so every value that enters a List or Map is boxed and unboxed behind your back. This chapter makes that cost and those traps visible, then fixes the arithmetic rules that quietly break solutions.

2.2 Overflow — the silent wrong answer

Java arithmetic never tells you it overflowed: int ops wrap around modulo 232. In C++ the same wrap is undefined behaviour; in Java it is defined and therefore quieter.

int a = 100_000, b = 100_000;
System.out.println(a * b);            // 1410065408  ← wrong! (10^10 mod 2^32)
System.out.println((long) a * b);     // 10000000000 ← correct: one operand long promotes the expression
long wrong = a * b;                   // ❌ still 1410065408: the multiplication already happened in int
long right = (long) a * b;            // ✅ widen BEFORE multiplying

// summing an array of 10^5 values up to 10^9 each -> 10^14: needs long
int badSum = 0;                       // ❌ overflows
long goodSum = 0; for (int v : arr) goodSum += v;

// midpoint: avoid lo + hi overflow when lo, hi are near Integer.MAX_VALUE
int mid = (lo + hi) / 2;              // ❌ overflow
int mid2 = lo + (hi - lo) / 2;        // ✅

// detect overflow explicitly when you must stay in int
try { int x = Math.multiplyExact(a, b); }
catch (ArithmeticException e) { /* overflow */ }

2.4 Boxing, unboxing and the Integer cache

Collections store references. List<Integer> means an array of pointers to Integer objects, so 1 becomes a heap object, costs ~16 bytes instead of 4, and is fetched through a pointer.

List<Integer> xs = new ArrayList<>();
xs.add(5);                       // autoboxing: int -> Integer.valueOf(5)
int y = xs.get(0);               // auto-unboxing: Integer.intValue()

// The cache trap: valueOf caches -128..127 (Boolean, Byte, Short, Character similarly)
Integer a = 127, b = 127;
System.out.println(a == b);      // true  — same cached object
Integer c = 128, d = 128;
System.out.println(c == d);      // false — two different objects!
System.out.println(c.equals(d)); // true  — always compare wrappers with equals

// NPE: unboxing null throws
Map<String,Integer> freq = new HashMap<>();
freq.put("a", null);
int n = freq.get("a");           // ❌ NullPointerException
int m = freq.getOrDefault("a", 0);  // ✅ 0

// Integer.compare is the overflow-safe comparator
Integer.compare(a, b);           // ✅
// a - b as a comparator ❌ overflows for extreme values (Comparator contract violated)
Trap: map.get(key) + 1 on a missing key throws NPE; map.get(key) == other on Integer values compares references for values outside the cache. Idiomatic fix: map.merge(k, 1, Integer::sum) or map.put(k, map.getOrDefault(k, 0) + 1).

3 Strings & characters

Java strings are immutable objects, not arrays. That single fact explains the O(n²) loops, the == failures, and why StringBuilder exists.

Strings without the O(n²) trap

A large share of interview problems are string problems: palindromes, anagrams, parsing, substrings, encoding. Almost all of them are solved with nine methods — length, charAt, toCharArray, substring, indexOf, split, equals, compareTo, and StringBuilder. This chapter is those nine, their exact index conventions, and the four ways people lose submissions with them.

3.1 Immutability and the cost it imposes

String s = "abc";
s.toUpperCase();              // returns "ABC" — s is still "abc"
s = s.toUpperCase();          // ✅ rebind the variable
String t = s.substring(1);    // "BC" is a NEW string; s is untouched

// The O(n^2) loop: 10^5 concatenations of 1 char copies ~5 x 10^9 chars
String bad = "";
for (int i = 0; i < n; i++) bad += 'a';        // ❌ quadratic in Java (unlike C++ std::string)

StringBuilder sb = new StringBuilder();
for (int i = 0; i < n; i++) sb.append('a');    // ✅ amortised O(n)
String good = sb.toString();

sb.reverse();                    // in-place reversal
sb.setCharAt(2, 'X');            // mutate one char
sb.deleteCharAt(0);              // O(k) shift
sb.insert(0, 'Z');               // O(k) — avoid in loops
System.out.println(sb.charAt(0));
Do not “fix” it with StringBuffer. StringBuffer is the synchronised (thread-safe) sibling; it is strictly slower and pointless in a single-threaded judge.

3.3 The four string traps that cost submissions

1 · substring(begin, end)

end is exclusive, so s.substring(i, i+1) is a one-char string. Mixing in the “take a single char” instinct from Python (s[i:]) produces off-by-one bugs at the last character.

2 · split takes a regex

s.split(".") returns an empty array (the dot matches everything). Escape metacharacters: split("\\."), split("\\|"), split("\\s+"). To split on a plain string without regex reasoning, use Pattern.quote(t).

3 · Trailing empties vanish

"a,b,,".split(",") → ["a","b"]. Pass a negative limit to keep them: split(",", -1) → ["a","b","",""].

4 · == on strings

Literals are interned, so "ab" == "a" + "b" is true by compile-time constant folding — while new String("ab") == "ab" is false. Any string produced at runtime must be compared with equals.
// Safe tokenising without regex — often what you want for "split by spaces"

StringBuilder cur = new StringBuilder();
for (int i = 0; i <= s.length(); i++) {
    char c = (i == s.length()) ? ' ' : s.charAt(i);
    if (c == ' ') { if (cur.length() > 0) { words.add(cur.toString()); cur.setLength(0); } }
    else cur.append(c);
}

// Splitting once and reusing saves the regex compile per call
String[] tokens = s.split(",");
for (String tok : tokens) { /* … */ }

// Parsing a CSV-ish line with empty fields preserved
String[] parts = line.split(",", -1);

// In-place spiral read of a matrix (boundary-shrinking skeleton)
List<Integer> spiral(int[][] a) {
    List<Integer> out = new ArrayList<>();
    int top = 0, bot = a.length - 1, left = 0, right = a[0].length - 1;
    while (top <= bot && left <= right) {
        for (int c = left; c <= right; c++) out.add(a[top][c]);  top++;
        for (int r = top; r <= bot; r++)  out.add(a[r][right]);  right--;
        if (top <= bot) for (int c = right; c >= left; c--) out.add(a[bot][c]); bot--;
        if (left <= right) for (int r = bot; r >= top; r--) out.add(a[r][left]); left++;
    }
    return out;
}   // O(m·n) time · O(1) extra space

// Remove duplicates from a sorted array, return the new length (classic two-pointer)
int removeDuplicates(int[] a) {
    int w = 0;                                    // write pointer
    for (int r = 0; r < a.length; r++)
        if (w == 0 || a[r] != a[w - 1]) a[w++] = a[r];
    return w;
}   // O(n) time · O(1) space

// Cyclic sort: put every value at its own index, then find the first mismatch
int firstMissingPositive(int[] a) {
    int n = a.length;
    for (int i = 0; i < n; i++)
        while (a[i] > 0 && a[i] <= n && a[a[i] - 1] != a[i]) {
            int t = a[i]; a[i] = a[t - 1]; a[t - 1] = t;
        }
    for (int i = 0; i < n; i++) if (a[i] != i + 1) return i + 1;
    return n + 1;
}   // O(n) time · O(1) space
Careful with the cyclic-sort swap: the loop must terminate when a value is already in place. Writing swap(i, a[i]-1) without the a[a[i]-1] != a[i] guard loops forever on duplicates.

// Prefix sums + HashMap = "subarray sum equals k" in O(n)
int countSubarrays(int[] a, int k) {
    Map<Integer,Integer> seen = new HashMap<>();
    seen.put(0, 1);                                  // empty prefix
    int sum = 0, count = 0;
    for (int v : a) {
        sum += v;
        count += seen.getOrDefault(sum - k, 0);      // count earlier prefixes with sum − k
        seen.merge(sum, 1, Integer::sum);
    }
    return count;
}   // O(n) time · O(n) space
Signals that a problem wants prefix sums: “subarray/submatrix sum”, “range sum query”, “count subarrays where …”, “equal number of 0s and 1s” (map 0 → −1 first), “number of subarrays divisible by k” (store the running sum mod k).

6.3 Binary search: the three templates

import java.util.function.IntPredicate;   // for the predicate-based templates below

// A · Exact search in a sorted ARRAY (returns index or -1)
int binarySearch(int[] a, int target) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;              // ✅ overflow-safe
        if (a[mid] == target) return mid;
        if (a[mid] < target) lo = mid + 1; else hi = mid - 1;
    }
    return -1;
}   // O(log n) time · O(1) space

// B · First index satisfying a monotone predicate ("leftmost true")
int lowerBound(int lo, int hi, IntPredicate ok) {  // [lo, hi] searchable range
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (ok.test(mid)) hi = mid; else lo = mid + 1;
    }
    return lo;
}

// C · Last index satisfying the predicate ("rightmost true")
int upperBound(int lo, int hi, IntPredicate ok) {
    while (lo < hi) {
        int mid = lo + (hi - lo + 1) / 2;          // ← the +1 avoids an infinite loop
        if (ok.test(mid)) lo = mid; else hi = mid - 1;
    }
    return lo;
}

// Examples of the predicate — the real skill
// smallest x with x*x >= n      : ok = mid -> (long) mid * mid >= n
// smallest capacity that ships  : ok = mid -> canShip(mid)
// leftmost insertion point for v: ok = mid -> a[mid] >= v
// real-valued answer (sqrt, rate): 200 iterations of the same loop with doubles
Recognising binary-search-on-answer problems: the phrasing says “minimise the maximum”, “maximise the minimum”, “smallest capacity/speed/days such that …”, or the answer is a number in a huge range with a cheap feasibility check. Constraints like n ≤ 105 with values up to 109 are a strong hint that O(n log V) is intended.

8.1 Disjoint Set Union (union-find)

class DSU {
    private final int[] parent, rank;
    private int components;

    DSU(int n) {
        parent = new int[n];
        rank = new int[n];
        components = n;
        for (int i = 0; i < n; i++) parent[i] = i;
    }

    int find(int x) {                       // path compression, iterative (no recursion depth risk)
        while (parent[x] != x) { parent[x] = parent[parent[x]]; x = parent[x]; }
        return x;
    }

    boolean union(int a, int b) {           // union by rank → O(α(n)) amortised
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;         // already connected: a cycle was found
        if (rank[ra] < rank[rb]) { int t = ra; ra = rb; rb = t; }
        parent[rb] = ra;
        if (rank[ra] == rank[rb]) rank[ra]++;
        components--;
        return true;
    }

    boolean connected(int a, int b) { return find(a) == find(b); }
    int count() { return components; }      // useful for “number of islands/provinces”
}
Signal in the statementWhy DSU
“connected components”, “provinces”, “friend circles”Union on each edge, then count roots
“would adding this edge create a cycle?” (Kruskal)union returns false exactly on a cycle
“grid cells connected 4-directionally”Map each cell to r * cols + c and union neighbours
“accounts merge”, “synonyms”, “equations”Union strings via a Map<String,Integer> id assignment
Grid DSU in one line: int id = r * cols + c;. Union right and down neighbours only — that covers all adjacency while visiting each pair once.

8.3 Trie (prefix tree)

class Trie {
    private final int[][] next = new int[100005][26];   // or a HashMap<Character,Integer> per node
    private final boolean[] end = new boolean[100005];
    private int nodes = 1;                              // node 0 is the root

    void insert(String w) {
        int cur = 0;
        for (int i = 0; i < w.length(); i++) {
            int c = w.charAt(i) - 'a';
            if (next[cur][c] == 0) next[cur][c] = nodes++;
            cur = next[cur][c];
        }
        end[cur] = true;
    }
    boolean contains(String w) {
        int cur = 0;
        for (int i = 0; i < w.length(); i++) {
            cur = next[cur][c(w, i)];
            if (cur == 0) return false;
        }
        return end[cur];
    }
    boolean startsWith(String p) {
        int cur = 0;
        for (int i = 0; i < p.length(); i++) {
            cur = next[cur][c(p, i)];
            if (cur == 0) return false;
        }
        return true;
    }
    private int c(String s, int i) { return s.charAt(i) - 'a'; }
}

8.4 Quickselect — O(n) average k-th element

// Median of an int array without a full sort (Lomuto partition)
int kth(int[] a, int k) {                    // k is 1-based: k = 1 gives the minimum
    int lo = 0, hi = a.length - 1, target = k - 1;
    java.util.Random rnd = new java.util.Random(42);
    while (true) {
        int p = lo + rnd.nextInt(hi - lo + 1);          // random pivot: avoids worst case on sorted input
        int t = a[p]; a[p] = a[hi]; a[hi] = t;
        int pivot = a[hi], i = lo;
        for (int j = lo; j < hi; j++) if (a[j] < pivot) { int tmp = a[i]; a[i] = a[j]; a[j] = tmp; i++; }
        int tmp = a[i]; a[i] = a[hi]; a[hi] = tmp;      // pivot to its final place: index i
        if (i == target) return a[i];
        if (i < target) lo = i + 1; else hi = i - 1;
    }
}   // O(n) average · O(n^2) worst case (randomisation makes it unlikely)
In interviews, Arrays.sort then a[k-1] is usually the right first answer (5 seconds of code, O(n log n)). Mention quickselect as the optimisation: “we can do it in expected O(n) with quickselect, which matters if the array is huge.” That sequence — simple first, then optimise — is exactly what the rubric rewards.

// Rolling rows: 0/1 knapsack in O(capacity) memory instead of O(n × capacity)
int knapsack(int[] w, int[] v, int cap) {
    int[] dp = new int[cap + 1];
    for (int i = 0; i < w.length; i++)
        for (int c = cap; c >= w[i]; c--)              // ⚠ downward: each item used once
            dp[c] = Math.max(dp[c], dp[c - w[i]] + v[i]);
    return dp[cap];
}
// Unbounded knapsack (coin change): the SAME loop, direction UP
// for (int c = w[i]; c <= cap; c++) dp[c] = Math.max(dp[c], dp[c - w[i]] + v[i]);
The direction of that inner loop is the whole difference between “use each item once” and “use each item any number of times”. Write the loop variable, then ask: when I read dp[c - w[i]], do I want the value from before this item or after?

// Sieve of Eratosthenes — all primes below n, O(n log log n)

10.4 Modular arithmetic — the “answer mod 109+7” drill

static final long MOD = 1_000_000_007L;

long add(long a, long b) { return (a + b) % MOD; }
long sub(long a, long b) { return (a - b % MOD + MOD) % MOD; }        // ⚠ negatives
long mul(long a, long b) { return (a * b) % MOD; }                   // a,b < 1e9 → product < 1e18 ✅ fits in long

long pow(long base, long exp) {                                       // fast exponentiation O(log exp)
    long r = 1; base %= MOD;
    while (exp > 0) {
        if ((exp & 1) == 1) r = r * base % MOD;
        base = base * base % MOD;
        exp >>= 1;
    }
    return r;
}

long modInverse(long a) {                                             // Fermat: a^(p−2) when p is prime
    return pow(a, MOD - 2);
}
long divide(long a, long b) { return a % MOD * modInverse(b) % MOD; } // “division” under a prime modulus

// nCr mod p with factorials (precompute once: O(n))
long[] fact, invFact;
void precompute(int n) {
    fact = new long[n + 1]; invFact = new long[n + 1];
    fact[0] = 1;
    for (int i = 1; i <= n; i++) fact[i] = fact[i - 1] * i % MOD;
    invFact[n] = modInverse(fact[n]);
    for (int i = n; i > 0; i--) invFact[i - 1] = invFact[i] * i % MOD;
}
long nCr(int n, int r) {
    if (r < 0 || r > n) return 0;
    return fact[n] * invFact[r] % MOD * invFact[n - r] % MOD;
}
Modulo is not distributable over subtraction in Java. (a - b) % MOD can be negative. Always ((a - b) % MOD + MOD) % MOD. The same applies to accumulating differences and to hash-code-style keys.

    seen[u] = true;
    for (int v : adj.get(u)) if (!seen[v]) dfs(v);
}
int components = 0;
for (int i = 0; i < n; i++) if (!seen[i]) { components++; dfs(i); }

// ---- Cycle detection (directed graph, three colours) ---------------------
// 0 = unvisited, 1 = on the current path, 2 = finished
int[] colour = new int[n];
boolean hasCycle(int u) {
    colour[u] = 1;
    for (int v : adj.get(u)) {
        if (colour[v] == 1) return true;        // back edge → cycle
        if (colour[v] == 0 && hasCycle(v)) return true;
    }
    colour[u] = 2;
    return false;
}

// ---- Topological sort: Kahn's algorithm (BFS over in-degrees) -------------
int[] indeg = new int[n];
for (int u = 0; u < n; u++) for (int v : adj.get(u)) indeg[v]++;

    int u = dq.poll();

}

// ---- Dijkstra: non-negative weights, O((V + E) log V) --------------------
long[] best = new long[n];
Arrays.fill(best, Long.MAX_VALUE);
PriorityQueue<long[]> pq = new PriorityQueue<>((x, y) -> Long.compare(x[0], y[0]));   // {dist, node}
best[src] = 0; pq.offer(new long[]{0, src});
while (!pq.isEmpty()) {
    long[] cur = pq.poll();
    long d = cur[0]; int u = (int) cur[1];
    if (d > best[u]) continue;                  // stale entry — skip it (essential!)
    for (int[] e : adjW.get(u)) {               // adjW holds {to, weight}
        int v = e[0]; long nd = d + e[1];
        if (nd < best[v]) { best[v] = nd; pq.offer(new long[]{nd, v}); }
    }
}
Mark visited at enqueue time (BFS) — not at dequeue. Marking late lets the same node enter the queue many times; on a dense grid that alone turns an O(V+E) BFS into a timeout.

// Grid BFS with an explicit distance grid — the workhorse for maze/step problems
int bfs(char[][] g, int sr, int sc, int tr, int tc) {
    int m = g.length, n = g[0].length;
    int[][] dist = new int[m][n];
    for (int[] row : dist) Arrays.fill(row, -1);
    int[] dr = {-1, 1, 0, 0}, dc = {0, 0, -1, 1};
    Deque<int[]> q = new ArrayDeque<>();
    dist[sr][sc] = 0;
    q.offer(new int[]{sr, sc});
    while (!q.isEmpty()) {
        int[] cur = q.poll();
        int r = cur[0], c = cur[1];
        if (r == tr && c == tc) return dist[r][c];
        for (int d = 0; d < 4; d++) {
            int nr = r + dr[d], nc = c + dc[d];
            if (nr < 0 || nr >= m || nc < 0 || nc >= n) continue;
            if (g[nr][nc] == '#' || dist[nr][nc] != -1) continue;
            dist[nr][nc] = dist[r][c] + 1;           // 8-directional? just add the 4 diagonals
            q.offer(new int[]{nr, nc});
        }
    }
    return -1;                                      // unreachable
}   // O(m·n) time · O(m·n) space

13.6 Sliding window, prefix sums, monotonic structures

// Longest substring with at most k distinct characters — the general template
int longestKDistinct(String s, int k) {
    Map<Character,Integer> cnt = new HashMap<>();
    int left = 0, best = 0;
    for (int right = 0; right < s.length(); right++) {
        char c = s.charAt(right);
        cnt.merge(c, 1, Integer::sum);
        while (cnt.size() > k) {                        // restore the invariant
            char d = s.charAt(left++);
            if (cnt.merge(d, -1, Integer::sum) == 0) cnt.remove(d);
        }
        best = Math.max(best, right - left + 1);        // window is valid here
    }
    return best;
}   // O(n) time · O(k) space

// Minimum window substring: “how many characters are still missing” as the state
int minWindowLen(String s, String t) {
    int[] need = new int[128];
    for (char c : t.toCharArray()) need[c]++;
    int missing = t.length(), left = 0, best = Integer.MAX_VALUE;
    for (int right = 0; right < s.length(); right++) {
        if (need[s.charAt(right)]-- > 0) missing--;      // useful character consumed
        while (missing == 0) {
            best = Math.min(best, right - left + 1);
            if (need[s.charAt(left++)]++ == 0) missing++; // giving back a needed char
        }
    }
    return best == Integer.MAX_VALUE ? 0 : best;
}   // O(n + m) time · O(1) space (alphabet-sized)

13.8 Backtracking — the four canonical shapes

// 1 · Subsets (include / exclude at each index) — O(2^n)
void subsets(int[] a, int i, List<Integer> cur, List<List<Integer>> out) {
    if (i == a.length) { out.add(new ArrayList<>(cur)); return; }   // ⚠ copy, don't add the reference
    subsets(a, i + 1, cur, out);                                     // exclude
    cur.add(a[i]); subsets(a, i + 1, cur, out); cur.remove(cur.size() - 1);   // include, then UNDO
}

// 2 · Permutations (choose any unused element at each level) — O(n! · n)
void perms(int[] a, boolean[] used, List<Integer> cur, List<List<Integer>> out) {
    if (cur.size() == a.length) { out.add(new ArrayList<>(cur)); return; }
    for (int i = 0; i < a.length; i++) {
        if (used[i]) continue;
        // duplicates: skip a repeated value at the same level (with the input SORTED)
        if (i > 0 && a[i] == a[i - 1] && !used[i - 1]) continue;
        used[i] = true; cur.add(a[i]);
        perms(a, used, cur, out);
        cur.remove(cur.size() - 1); used[i] = false;                 // undo in reverse order
    }
}

// 3 · Combinations of size k (start index prevents permutations of the same set) — O(C(n,k)·k)
void combos(int n, int k, int start, List<Integer> cur, List<List<Integer>> out) {
    if (cur.size() == k) { out.add(new ArrayList<>(cur)); return; }
    for (int v = start; v <= n; v++) {
        cur.add(v); combos(n, k, v + 1, cur, out); cur.remove(cur.size() - 1);
    }
}

// 4 · Grid / board search with pruning (word search, N-Queens, sudoku)
boolean dfs(char[][] b, int r, int c, String w, int k) {
    if (k == w.length()) return true;
    if (r < 0 || r >= b.length || c < 0 || c >= b[0].length || b[r][c] != w.charAt(k)) return false;
    char saved = b[r][c];
    b[r][c] = '#';                                   // mark visited IN the board (no extra memory)
    boolean found = dfs(b, r+1, c, w, k+1) || dfs(b, r-1, c, w, k+1)
                 || dfs(b, r, c+1, w, k+1) || dfs(b, r, c-1, w, k+1);
    b[r][c] = saved;                                 // always restore before returning
    return found;
}

// Streaming median: max-heap of the smaller half + min-heap of the larger half
PriorityQueue<Integer> low = new PriorityQueue<>(Comparator.reverseOrder());   // max-heap
PriorityQueue<Integer> high = new PriorityQueue<>();                          // min-heap
void add(int x) {
    low.offer(x);
    high.offer(low.poll());                      // every low element passes through high
    if (high.size() > low.size()) low.offer(high.poll());   // keep |low| == |high| or |low| = |high|+1
}
double median() {
    return low.size() > high.size() ? low.peek() : (low.peek() + high.peek()) / 2.0;
}   // add O(log n) · median O(1)
Two-heap invariant, memorised: every insertion goes into low first, then the largest of low moves to high, then if high grew bigger than low its smallest moves back. After that, low holds the smaller half (as a max-heap), so low.peek() is the median for odd sizes.

15.1 Language & semantics

Why is String immutable?

Safety (safe to share across threads, safe as a HashMap key), caching (literals are interned, hashCode is computed once), and security (file paths, class names). The cost: every “modification” allocates — hence StringBuilder for loops.

== vs equals?

== compares primitives by value and references by identity. equals is the value contract; the standard library implements it — your own classes only get it if you write it (or if you use a record).

Why is String a good HashMap key and int[] a bad one?

Strings override hashCode/equals by content and are immutable. Arrays use identity semantics and are mutable — wrap them in a List.of(...), a packed long, or a record.

Autoboxing cost, in one sentence?

Every int that enters a collection becomes a ~16-byte object reached through a reference, so prefer int[] in hot loops — and remember the −128…127 cache is why == “works” in small tests.

final, static, static final?

final: the reference/variable cannot be reassigned. static: belongs to the class. static final: a constant. Beware static mutable state in a Solution — it persists between test cases.

Checked vs unchecked exceptions?

Checked must be declared or caught (IOException); unchecked (RuntimeException family: NPE, AIOOBE, IAE) do not. In interview code, prefer unchecked — you should not be writing throws everywhere.

When does StringBuilder matter?

Whenever you concatenate in a loop: s += c is O(n²), sb.append(c) is amortised O(1) and one toString at the end.

What is var and is it “dynamic typing”?

Local variable type inference (Java 10+): the type is still static and fixed at compile time, just not spelled out. Use it when the initialiser makes the type obvious.

15.2 Collections & complexity

ArrayList vs LinkedList?

ArrayList wins almost always: O(1) random access, contiguous memory, no node overhead. LinkedList only helps with O(1) insertion at a known node — and ArrayDeque is the better queue in every case.

HashMap vs Hashtable vs ConcurrentHashMap?

HashMap is the single-threaded default (allows one null key); Hashtable is legacy and synchronised; ConcurrentHashMap is the safe concurrent one (no nulls) and uses lock striping.

How does HashMap work inside?

Array of buckets indexed by hash(key) & (capacity-1); collisions become a linked list, which converts to a red-black tree (treeifies) once a bucket holds 8 entries — that is why worst-case lookup is O(log n), not O(n), for hostile inputs.

When does a HashMap resize?

At load factor 0.75 of the capacity (default 16); each resize doubles the table and rehashes. To avoid it: new HashMap<>(expected * 4 / 3 + 1).

HashSet vs TreeSet?

HashSet: O(1) average, unordered. TreeSet: O(log n), sorted, with floor/ceiling/higher/lower. Choose by whether you need order or range queries — not by habit.

Why is PriorityQueue not sorted when iterated?

It is a binary heap in an array: the heap property only guarantees the root is the extreme. Sorted output requires repeated poll.

Stack or ArrayDeque for DFS?

ArrayDeque: Stack extends Vector and is synchronised (slower), and ArrayDeque has better locality than LinkedList.

How do you find the k largest elements?

A min-heap of size k: O(n log k) time, O(k) memory. Sorting is O(n log n) — mention both and pick by constraints.

How does TreeMap answer “nearest value” questions?

floorKey and ceilingKey give the nearest keys ≤ / ≥ a target in O(log n) — the standard tool for calendar/schedule or “closest temperature” problems.

What is the complexity of a HashMap lookups with poor hashCode?

Everything lands in one bucket: O(n) (Java 8+ treeifies to O(log n)). The practical fix is a better key or a cheap encoding.

15.3 Performance, pitfalls and judgement

Your Java solution TLEs at the “right” complexity. What do you check?

Boxing in the hot loop, String concatenation, ArrayList.remove(0), rebuilding maps/trees per query, streams in tight loops, recursion overhead. Fix in that order.

int or long for the answer?

long whenever sums or products can exceed 2.1 × 109 — including mid-computation values that are later reduced mod 109+7.

How do you avoid StackOverflowError?

Convert deep recursion to an explicit ArrayDeque stack (or increase -Xss if you control the JVM). ~104–105 frames is the practical ceiling.

Why does my answer differ on the last test case only?

Classic causes: a static/instance field surviving between test cases, an unsorted assumption, or an overflow that only appears at maximum values.

How would you test this without a judge?

The 3-level loop: samples plus edge cases, then a randomised stress test against a brute force with a fixed seed, then one max-size timing run.

What would you do with 10× more time?

Name a concrete improvement with its complexity (“replace the O(n²) scan with a monotonic stack for O(n)”), not a vague “optimise”.

// 1 · Two Sum — hash map complement, O(n) ---------------------------------
int[] twoSum(int[] nums, int target) {
    Map<Integer,Integer> seen = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        int need = target - nums[i];
        if (seen.containsKey(need)) return new int[]{seen.get(need), i};
        seen.put(nums[i], i);
    }
    return new int[0];
}

// 2 · Reverse a linked list — iterative pointer surgery, O(n) --------------
ListNode reverseList(ListNode head) {
    ListNode prev = null;
    while (head != null) { ListNode nxt = head.next; head.next = prev; prev = head; head = nxt; }
    return prev;
}

// 3 · Maximum subarray — Kadane's algorithm, O(n) -------------------------
int maxSubArray(int[] a) {
    int best = a[0], cur = a[0];
    for (int i = 1; i < a.length; i++) { cur = Math.max(a[i], cur + a[i]); best = Math.max(best, cur); }
    return best;
}

// 4 · Valid parentheses — stack, O(n) -------------------------------------
boolean isValid(String s) {
    Deque<Character> st = new ArrayDeque<>();
    for (char c : s.toCharArray()) {
        if (c == '(' || c == '[' || c == '{') st.push(c);
        else {
            if (st.isEmpty()) return false;
            char o = st.pop();
            if ((c == ')' && o != '(') || (c == ']' && o != '[') || (c == '}' && o != '{')) return false;
        }
    }
    return st.isEmpty();
}

// 5 · Binary search — exact search, O(log n) ------------------------------
int search(int[] a, int target) {
    int lo = 0, hi = a.length - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] == target) return mid;
        if (a[mid] < target) lo = mid + 1; else hi = mid - 1;
    }
    return -1;
}

// 6 · Merge two sorted arrays in place — from the back, O(m + n) ----------
void merge(int[] a, int m, int[] b, int n) {
    int i = m - 1, j = n - 1, k = m + n - 1;
    while (j >= 0) a[k--] = (i >= 0 && a[i] > b[j]) ? a[i--] : b[j--];
}

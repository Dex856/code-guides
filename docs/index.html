Where the code actually runs. Compilers cannot live inside a static website, so the terminal talks to a small local server (python3 tools/practice_server.py) that ships with the project — that is the copy you get in the workspace preview. On a plain static host (like GitHub Pages) the same page still loads, loads problems and lets you edit, save and copy code; it just tells you that running needs the server. Nothing is sent anywhere else: the server only ever runs your code locally, with a timeout, a CPU limit and capped output.

04How the three fit together

Pick one language as your interview weapon and use the others for context. The chapters, the diagrams and the templates are deliberately parallel: the same problem is solved with the same pattern in each language, so you can compare priority_queue, PriorityQueue and heapq side by side and stop confusing their conventions.

Suggested path: read the guide for your language end to end (2–3 hours), then work the question bank topic by topic — one topic per session, easy first, then medium, then hard. Inside a bank you can filter by difficulty, collapse the topic list, and mark problems done to watch the counter fill up. The bank pages mirror the guide chapters, so any term you do not recognise links back to the explanation.

05Offline by design

Every page in this site is a single HTML file with inline CSS, inline JavaScript and inline SVG. There are no fonts, scripts, images or analytics loaded from anywhere. Download the folder, open index.html, and everything works — on a plane, in an exam room, or ten years from now.

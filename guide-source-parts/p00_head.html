1 Python in 2026 — versions, install, environment

What Python is, which version to use, and how to get a clean, isolated setup on any OS.

1.1 What Python actually is

Python is a high-level, dynamically typed, garbage-collected, multi-paradigm language whose reference implementation (CPython) compiles source to bytecode and interprets it on a virtual machine. It is also the glue language of computing: most modern Python is a thin layer of Python calling fast C, C++, Rust or GPU code (NumPy, PyTorch, polars, pydantic, uv).

Design philosophy

PEP 20 “The Zen of Python” — readability counts, explicit beats implicit, simple beats complex. Run import this.

Execution model

Compiled to bytecode → executed by the PVM on a stack machine. No compile step you manage; .pyc files cache bytecode.

Typing

Dynamically typed at runtime, optionally statically type-checked by tools (mypy/pyright/ty) via annotations. Types are never enforced at runtime by the language.

1.2 Which version should you use?

Since PEP 602, Python ships one feature release per year in October, supported for 5 years (2 years bugfix + 3 years security). In 2026 you should be targeting 3.12+ in production and learning on 3.13/3.14.

VersionHeadline features you will actually use
3.9dict | dict merge, str.removeprefix/suffix, generic builtins in annotations list[int].
3.10match/case, X | Y union types, zip(strict=True), far better error messages.
3.11 big winAdaptive interpreter: 10–60% faster than 3.10; ExceptionGroup/except*; tomllib; task groups arrive in asyncio; self-typed Self.
3.12PEP 695 type X = …, class C[T]:, def f[T](); f-strings can reuse quotes and span lines; per-interpreter GIL; itertools.batched; sys.monitoring.
3.13Experimental JIT and free-threaded (no-GIL) build; improved REPL; copy.replace(); random CLI; dead-battery modules removed.
3.14 currentFree-threading officially supported (PEP 779); t-strings (PEP 750); deferred annotations (PEP 649); compression.zstd; multiple interpreters in stdlib (PEP 734); incremental GC; UUID 6–8; colour REPL; zero-overhead remote debugging (PEP 768).
3.15 newfrozendict builtin (PEP 814); explicit lazy imports (PEP 810); sentinel() builtin (PEP 661); dedicated profiling package + Tachyon sampling profiler (PEP 799); UTF-8 default file encoding (PEP 686); upgraded JIT; free-threading installed by default on macOS builds.
Reality check for 2026: the free-threaded build and JIT are real but optional. The default python3 you install is still the GIL build. Choose free-threading only when a benchmark on your workload shows a win (multi-threaded CPU work), and expect ~5–15% slower single-threaded code in exchange.

$ python3 -m site       # where do site-packages live for THIS interpreter?

1.5 Create a project in 60 seconds (the 2026 way)

# --- Option A: uv (fastest; recommended for new projects) -------------------
$ uv init my-app        && cd my-app      # creates src layout + pyproject.toml
$ uv python pin 3.14                     # writes .python-version
$ uv add requests httpx                  # adds deps + uv.lock
$ uv add --dev pytest ruff mypy          # dev tools in [dependency-groups]
$ uv run python -c "print('hello')"      # runs inside the project env — no activate needed
$ uv run pytest -q

# --- Option B: classic venv + pip ----------------------------------------
$ python3 -m venv .venv
$ source .venv/bin/activate              # Windows: .venv\Scripts\activate
(.venv) $ python -m pip install -U pip
(.venv) $ python -m pip install requests pytest
(.venv) $ python -c "import requests; print(requests.__version__)"
$ deactivate

# --- Option C: Poetry (mature, great for libraries) ----------------------
$ pipx install poetry
$ poetry new my-lib --src && cd my-lib
$ poetry add httpx        # dependency
$ poetry add -G dev pytest
$ poetry run python -m my_lib

Never again: “it works on my machine” → commit pyproject.toml + uv.lock (or poetry.lock). A lock file pins the exact version and hash of every transitive dependency for every platform.

1.6 Editors and notebooks

VS Code (most popular)

Install Python, Pylance (types + autocomplete), Ruff, Jupyter. Select the interpreter with Ctrl/Cmd+Shift+P → “Python: Select Interpreter” → your .venv. Set "python.analysis.typeCheckingMode": "basic" to catch bugs as you type.

PyCharm / PyCharm CE

The best refactoring and debugger experience for large codebases. Community edition is free and includes type-aware inspection, pytest runner and a database tool window.

Cursor / Zed / Neovim

AI-first editors (Cursor) or speed (Zed, Neovim + pyright + ruff-lsp). Neovim: nvim-lspconfig + pyright + ruff gives you the same engine as VS Code.

Jupyter / marimo

Use JupyterLab for data exploration; marimo or jupytext if you want notebooks that diff cleanly in git. Rule: notebooks for exploring, modules + tests for shipping.
REPL upgrades worth knowing (3.13/3.14): the default python REPL now has colour syntax highlighting, multi-line editing, F1 for help, F2 for history, F3 paste-mode and block-level undo. For a richer shell install pip install ipython (tab-completion of attributes, %magic, obj?).

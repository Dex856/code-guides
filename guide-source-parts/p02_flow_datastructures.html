4.1 Conditionals

# Ternary — prefer explicit if/else when it stops being readable
status = "adult" if age >= 18 else "minor"
label = "even" if n % 2 == 0 else "odd"

# Chained comparisons read like maths
if 0 <= score <= 100:
    ...

# Truthiness, not "== True"
if items:            # non-empty container
    ...
if not items:        # empty
    ...
if x is None:        # identity — always for None
    ...
if x is not None:
    ...

# 3.10+ structural pattern matching — branches on SHAPE, not just value
match command.split():
    case ["go", direction]:                       # exactly 2 items, first is "go"
        move(direction)
    case ["go", direction, *rest]:                # 2+ items
        move(direction, rest)
    case ["look"] | ["l"]:                        # alternatives
        look()
    case {"action": action, **rest} if action:    # dict pattern + guard
        do(action, rest)
    case Point(x=0, y=0):                         # class pattern (duck-typed)
        print("origin")
    case int() | float() as n if n > 0:           # capture with `as`
        print("positive number", n)
    case _:                                       # wildcard — default branch
        raise ValueError(f"unknown: {command}")

# Classic dispatch alternative: dict of functions beats long if/elif chains
HANDLERS = {"go": move, "look": look, "quit": quit}
HANDLERS.get(cmd, lambda *_: print("?"))(arg)
match is not switch. It compares structure using == for literals, supports unpacking, class patterns and guards, and a bare name like case x: is a capture (matches everything), not a comparison — use case Point(): or dotted names (case Color.RED:) for value matching.

4.3 while, and why loops are slower than they look

while (line := f.readline()):
    process(line)

# Retry with backoff — the practical while-loop idiom
import random, time
for attempt in range(5):
    try:
        result = fetch()
        break
    except TimeoutError:
        time.sleep(2 ** attempt + random.random())   # 1, 2, 4, 8, 16s + jitter
else:
    raise RuntimeError("gave up after 5 attempts")
Performance rule of thumb: in CPython the interpreter overhead per bytecode instruction dominates. Moving work from a Python-level loop into C-level builtins is the cheapest big win: sum(x*x for x in xs) beats a manual accumulator loop, and numpy/polars beat both by 10–100×. See ch. 17.

Stability matters: Python's Timsort is stable, so “sort by A, then by B” gives you a multi-key sort for free — the last sort dominates. reverse=True does not break the stability guarantee.

5.6 Comprehension syntax — all four forms

[x * 2 for x in range(5)]                    # list  → materialised
{x * 2 for x in range(5)}                    # set   → deduplicated, unordered
{x: x * 2 for x in range(5)}                 # dict  → key: value
(x * 2 for x in range(5))                    # generator → lazy, single-use, lowest memory

# with condition and nesting
[x for x in xs if x > 0]                      # filter
[(x, y) for x in xs for y in ys if x != y]   # nested loops (same order as nested for)
{x: [i for i, v in enumerate(row) if v] for x, row in grid.items()}

# Reading order is important: value first, then the loops in for-order
flat = [item for row in matrix for item in row]     # flatten (NOT [row for item ... ])

# Walrus inside a comprehension avoids double work
results = [y for x in data if (y := transform(x)) is not None]

# Anti-pattern: side effects in a comprehension
[print(x) for x in xs]        # ✗ builds a useless list — use a plain for loop
[x for x in xs if len(set(x)) == len(x)]      # ✓ transform + filter, no side effects
